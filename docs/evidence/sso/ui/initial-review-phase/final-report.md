# SSO/OIDC 浏览器与设计 QA

18 项操作检查、10 张 1440×1050 截图已完成。源码身份见 `qa.json`，截图均逐张查看像素；无浏览器凭据、Cookie、授权码、state 或 Token 原文进入证据。

1. 列表及配置：真实列表、新增平台/组织配置、名称保存、分阶段测试、默认及认证修订、启停均接入服务端。长名称和 Issuer 在列表截断，详情输入可水平查看，整个页面没有水平溢出。[列表](02-provider-list.jpg)、[配置](03-provider-drawer.jpg)、[长字段](09-long-fields.jpg)。
2. 并发及未保存保护：第二管理员真实改名后，旧修订保存得到412；草稿保持，需读最新并明确采用后才可保存。Escape 不会直接丢弃输入，必须明确放弃。[冲突](06-conflict.jpg)。
3. 显式用户：无密码预创建；Active绑定只读，停用后可修正，角色和范围继续走原流程。修正真实写入已验证；没有自动开户或邮箱合并。[用户表单](04-sso-user.jpg)。
4. 企业登录：原生同源POST跳转真实Keycloak，跨站GET回调携带临时Lax Cookie。Strict平台Cookie与CSRF Cookie在跨站回调、跨站完成页请求中均没有发送；完成页后的同源me请求恢复平台身份，重新获得CSRF后真实改名成功。[身份服务](07-keycloak.jpg)、[布尔协议事实](cookie-evidence.json)。
5. 失败与恢复：未知Subject、错误客户端秘密返回通用可追踪提示；prompt=login要求重新验证，中途浏览器返回仍可本地登录。SSO用户停用自己的身份源后，后续请求401并回登录；原合成fixture-admin可登录恢复。[错误](08-generic-failure.jpg)。
6. 撤权：保留功能码但撤真实系统PlatformAdmin角色，刷新会话后私有详情和引用草稿清空。释放此前已授权、被测试代理延迟的响应，仍为dialog0/referenceInputs0。[撤权](10-permission-revoked.jpg)。
7. 键盘：抽屉焦点循环、Escape、未保存确认可操作；只读绑定详情Tab保持在弹窗内且Escape关闭。新表单沿用原Editor标签与键盘逻辑。

本批设计保留原第39页的深色侧栏、蓝色主操作、浅灰工作区、密集表格及层级。生产控制台采用既有企业Shell；新增修订和测试阶段帮助区分保存、连接测试与真实登录状态，不把原原型的模拟Success当作真实结果。

QA修复已在新冻结源码重新构建和复验：登录嵌套表单恢复18px间距与全宽CTA；侧栏当前SSO条目从视口外滚动到可见；绑定只读详情增加焦点循环与Escape关闭。[登录](01-login.jpg)、[测试阶段](05-test-stages.jpg)。

边界：部分CRUD、默认及轮换先在前一构建验证，相关后端未再改变；最终构建又验证新增组织源、名称写入、测试、启停、冲突、撤权、企业登录和恢复。没有进行完整WCAG认证、全站屏幕阅读器、企业IdP或生产TLS/PKI验收。合成fixture的测试代理只记录请求类型、Fetch-Site与Cookie存在布尔值，不进入正式产品。
