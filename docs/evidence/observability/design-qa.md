# 第 28–33 页真实数据设计 QA

本轮使用本机隔离 Control Plane、PostgreSQL、两个 Gateway、两个独立 Worker、Collector、Prometheus、Loki、Tempo。控制台采用正式构建文件，无热更新；临时浏览器代理保留原 Host、Origin 和 CSRF 校验，身份仅属于本次可销毁验收项目。

| 步骤 | 页面与操作 | 观察结果 |
|---|---|---|
| 1 | 28 监控总览：选择 P99 趋势、P95 排名 | 选择写入 URL；七种真实趋势口径；两 API 的请求量 / P95 / P99 排名另有不同排序的服务端断言 |
| 2 | 29 API 监控：从资源名称进入 | 保留当前 API 与授权环境；未完整采集的一小时历史明确显示 Partial，不伪造指标 |
| 3 | 30 访问日志：真实 Loki 分页 | 第一页 50 条，下一页 50 条；固定查询截止时间与游标；日志可关联 Trace |
| 4 | 31 Trace：两层瀑布图、span 详情、源故障重试 | 普通无上游 Trace 头请求有真实根 Server 与子 Client；详情显示实际耗时和安全字段；Tempo 超时清除旧详情，恢复后自动及手动重试均恢复选中 URL 的详情 |
| 5 | 32 告警中心：确认、查看恢复时间线 | 实际写入 Ack；恢复事件操作不可用；自动恢复明确显示系统 / Recovered，历史观察与当前有效观察区分 |
| 6 | 33 告警规则：预览范围、只读测试 | 预览一个实际活动环境；健康指标值 0，当前条件不成立；规则修订保持 1，不推进持续时间或生成事件 |

六页均核对桌面宽度 1440px、文档宽度 1440px，无页面水平溢出。独立正常浏览器会话未记录 console error；刻意引入的 503 与测试代理初次 403 单独记录，不并入正常会话结论。

设计检查发现并修正：告警详情缺少字段栅格样式；自动恢复详情误写“未解决”；源恢复列表成功后选中链路详情未重开。规则长表单内部滚动属于既有布局，截图分别保留列表与测试结果。当前视觉健康度：六页可用、状态与权限边界清楚；这是聚焦桌面体验 QA，未声明完整 WCAG 合规或生产容量验收。
