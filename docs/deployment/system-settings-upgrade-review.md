## 失败与回退

- 构建失败：保持原环境，无停机。
- 冷备份或恢复验证失败：使用保留的旧release启动原声明服务，不继续迁移/切换。
- 迁移失败：立即停止升级，查明事务和数据库实际状态；不能仅换旧镜像就宣称数据库已回滚。EF的事务迁移应核对迁移历史和表是否存在，不删除数据处理失败。
- 迁移成功但新软件验收失败：此次为新增空表且不改快照协议，可用旧release恢复软件并验证原代理；保留新表/迁移记录，旧UI不能管理新配置。不得自动执行migration Down删除设置表。该软件回退方式须在恢复夹具上验证后才能用于原实例。
- 重新发布之后：先核对新快照与原业务内容和协议一致；正常发布回滚和双ACK仍走既有流程，不能伪造ACK。若无法软件回退，使用已验证冷备份在独立项目恢复，保留原卷并另行明确切换，不能覆盖原数据强行恢复。
