# JWT／重试／缓存运行维护

本批软件不会自动改变业务发布版本。JWT 使用管理员提供的固定公开 JWKS；业务 JWT 与控制台 SSO 会话相互独立。缓存只用于合格公共 GET 响应，不保证即时一致。重试最多 3 次物理尝试，只用于可安全重放的 GET／HEAD，并共享路由总超时。

## 私有缓存密钥

新源码的部署定义增加 `secrets-cache` 卷。初始化入口从当前部署的私有目录读取 `secrets/cache-hmac`，双网关均以只读方式挂载 `/run/cache`，其他业务进程不能读取该卷。文件为 32 字节随机值的规范 Base64 文本，目录权限 0700、文件权限 0600；Docker 卷内归 UID 10001 所有。节点原认证 Secret、数据库密码、SSO client 和审批账号不改变。

`cache-secret-receipt.json` 绑定部署 owner、project、路径与文件 SHA256，仅存于私有运行目录。已有 receipt 但缺文件、校验不符、非私有文件或符号链接均拒绝启动，禁止临时生成新密钥来“修复”。初次创建中断留下的规范私有文件可登记 receipt，保持同一字节值。需先调查归属，再从匹配的冷备恢复；密钥轮换会造成缓存冷启动，应另行安排。

新入口 `scripts/local-runtime.sh` 按 release 内的不可变提交归档读取部署定义。归档支持缓存时校验文件和共享卷 SHA；历史归档保持旧行为。现存固定工具目录不会重写。正式升级以本批固定归档中的新工具执行，保留旧工具用于检查历史版本。启动前确认默认缓存预算（全局 64 MiB／2000 条，单条最多 1 MiB）及实际 `policy.read` limits，浏览器不能放宽这些上限。

## 冷备与恢复

冷备包括原 PostgreSQL／LKG／数据保护／遥测卷、私有 secrets 和 SSO 配置；支持缓存的部署额外包含 `secrets-cache.tar` 及 receipt。所有文件逐 SHA 回读。备份暂停平台服务后，在 `finally` 中重新启动声明的原服务并等待可用；失败也执行恢复。冷备目录只能放在私有区域，禁止进入交付 ZIP。

恢复只允许新 UUID、独立端口、空目录和自有卷。receipt 随克隆重新绑定新 owner，密钥 SHA 保持相同；已初始化缓存卷与备份中的密钥再次比对，不能覆盖不匹配的文件。原 SSO 绑定在克隆中保持禁用，专用测试发行方与原 Keycloak 分离。

## 软件降级门禁

`canRestoreSoftware` 必须读取当前目标 Snapshot 和两节点 LKG 的实际协议版本，任何缺失／未知协议／读取失败都拒绝降级。2.2 运行快照不能装入最多支持 2.1 的旧镜像。先经正常业务审批回滚至兼容快照，确认双节点真实 ACK 和 LKG，再进行软件切换。门禁始终返回 `restoreDatabase=false`：不能拿旧库备份覆盖升级后新增的业务数据。

本机克隆验收、双网关验证和生产容量验收分别记录。外部通知与跨环境审批属于后续批次，本批没有实现。部署结果以独立升级报告和实际镜像 SHA 为准，本文不代表已经安装。
