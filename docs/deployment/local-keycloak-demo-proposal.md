# 本机持久 Keycloak SSO 演示接入方案

状态：用户已选择独立本机Keycloak演示；本具体部署方案待确认，尚未新增服务、身份源或账号。

## 目标与范围

复用已部署0b42f9e的OIDC授权码/PKCE登录和显式平台账号治理。4192仍为唯一平台入口，4196/4197仍为现有双网关。原admin、两名审核员、密码、角色、范围、业务配置及历史数据保留。

本批是现有SSO与本机生命周期工具的部署扩展，不新增应用认证协议。成功标准：真实Keycloak登录后进入4192，演示用户仅能读取指定本机组织/项目/环境；常规重启后身份源、用户、秘密映射和会话仍有效；停用身份源或绑定后会话撤销，本地管理员持续可登录。

## 持久部署

- 独立Docker Compose项目、owner、Keycloak和独立PostgreSQL数据卷；不使用验收临时fixture的数据卷或测试镜像。
- 复用已锁定的Keycloak 26.8.0镜像摘要；新增端口拟4193，仅绑定127.0.0.1，实施前检查冲突。数据库不发布宿主端口。
- 单独realm `webapi-local-demo`、client `webapi-console-local`，关闭注册、直接密码授权和隐式授权，只用授权码与S256 PKCE。
- Keycloak加入经原owner核对的运行网络，使用明确的独立网络别名。浏览器Issuer采用 `http://localhost:4193/realms/webapi-local-demo`；平台回调采用 `http://127.0.0.1:4192/auth/oidc/callback/{实际ProviderID}`，在创建Provider后精确登记，不使用通配符。
- 本机HTTP例外仅在Development和FixtureEnabled=true时启用，精确允许localhost:4193并将该Origin的后端连接映射到Keycloak容器。URL、Host和Issuer不改写；不启用故障代理，不放开任意私网或公网Origin。此设置仅用于本机演示，正式环境继续要求HTTPS且FixtureEnabled=false。
- 客户端秘密及IdP密码随机生成，保存在私有0600文件，不打印、不进入Git或公开交付。客户端秘密只读挂载给控制面，容器内保留受保护文件权限。

## 平台账号与权限

新增明确标记为“本机SSO演示”的身份源，不设自动跳转或自动默认登录。先连接测试，随后启用。新增 `sso-demo-viewer`，绑定Keycloak真实稳定Subject，仅授予Viewer角色和现有本机组织/项目/环境的读取Scope；没有本地密码，不授予管理员、审批、凭证管理或发布权限。

不修改原三账号、不转成本机SSO、不自动开户、不按邮箱匹配或合并账号、不读取Claim授予权限。演示完成后保留该身份源、用户和IdP持久数据供操作。

## 生命周期与备份

扩展现有部署工具读取owner受控的持久SSO连接配置，覆盖常规start/restart/configure和冷备份/恢复入口，避免仅手动修改runtime-config.json导致下一次启动丢失配置。支持明确停用/回退入口，不能绕过owner校验或删除原卷。实现工作在独立工作树完成，主工作区原修改保留。

平台应用镜像及协议不需要变化；如果实施发现必须修改应用程序，先记录差异和范围，不借部署扩展悄悄改变既有SSO行为。新增已验收部署工具可固定一次本地提交，不push/merge，不包含秘密、运行数据或其他工作区修改。

实施前备份原平台数据、密钥和运行配置；Keycloak数据库和秘密纳入独立备份。验证新owner空卷恢复，不能把原卷存在或restart成功当作备份证明。停机只用于必要备份/控制面切换；双网关业务配置仍为原v4/seq4，不借SSO接入创建业务版本。
