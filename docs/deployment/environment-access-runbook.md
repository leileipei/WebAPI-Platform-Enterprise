# 环境访问地址运行手册

范围：环境级公开/内网入口和外部前缀、实际 Route 地址、环境文档副本、发布执行地址历史。本机隔离验收与原4192安装结果单独记录；生产 DNS/TLS/LB 验收不在本批范围。

## 配置与使用

组织与项目 → 环境管理 → 编辑环境。公开地址只填写 Origin，例如 `https://api-test.company.com`；生产环境必须 HTTPS。可选内网入口只对具备环境编辑权限及实际可写 Scope 的账号返回。API 外部路径前缀默认 `/`，例如 `/gateway`。地址元数据保存不修改 Route、Snapshot 或 Destination，也不发起入口开通或联网探测。

每环境使用独立域名，尽量保持 Route 相同。业务上游仍配置在 Destination。实际调用地址为 `公开 Origin + 外部前缀 + Route`，前缀必须由反向代理剥离。配置前缀不改变 Gateway 的监听路径。DNS、证书、负载均衡、可信代理和防火墙由运维部署配置。

API 详情和路由页明确区分工作配置与运行配置。运行入口只有实际成功发布和全部当前节点确认相符时显示。模板包含占位符时必须由调用者填写；复制示例不包含凭证。文档下载生成副本，原契约、API 修订和 Artifact 不变。单文件环境文档必须在仅含导出文件的解析环境中引用闭合；需要伴随文件或原始来源地址的契约返回明确422，完整固定来源包保留，不返回含缺失引用的下载文件。多文件打包或安全内联导出属于后续能力。未配置入口或运行状态不可确认时不会替代为最新版本。

发布详情保留本次执行时的地址，当前地址变化另行提示。回滚运行快照不会恢复环境地址、DNS、LB 或证书；历史验证不代表新入口已通过验证。旧发布显示“历史未记录”。

## 可重复验收

设置 `WEBAPI_NODE`、`WEBAPI_PNPM` 为现有工具路径；可选 `WEBAPI_NUGET_SEED_VOLUME` 只读复用锁定依赖缓存；浏览器可用 `WEBAPI_PLAYWRIGHT_PACKAGE` 和 `WEBAPI_BROWSER_EXECUTABLE` 指定已安装运行时。不修改依赖锁文件。

分别运行 `scripts/check-environment-access.sh domain`、`integration`、`gateway`、`console`。运行 `e2e 固定40位SHA` 会按固定提交归档构建，创建 UUID 容器项目、随机端口、随机秘密及独立数据；执行真实浏览器、真实双节点审批发布、TLS 代理前缀剥离和实际回滚。测试证书仅用于专用回环代理，客户端严格固定该证书信任，不关闭 TLS 校验。秘密不进入公开证据，清理仅允许项目与 owner 均匹配的资源。

`browser 固定SHA` 同样执行完整独立验收，避免复用其他实例的截图身份。截图输出在 `docs/evidence/environment-access/SHA/ui/`。逐张查看并确认实际视觉质量后记录 `visualReviewComplete=true`，运行 `verify 证据目录`；未检查截图、错误身份、伪 PNG、缺少迁移、模拟检查或未清理资源都不能通过。自动页面断言通过不等于人工视觉确认。证据检查器验证字节和身份一致性，并不替代源码审查或证明业务截图内容。

## 原4192升级与恢复

1. 只读核对原 `.runtime/local` 的 owner、固定镜像和源码身份、4192/4196/4197端口、环境绑定、用户和业务数据、SSO配置与IdP、观测源和实际卷；记录当前状态，不沿用旧报告的状态。
2. 保持原目录已有修改和原账号秘密。使用独立候选 SHA 镜像；不自动合并或提交原目录。两项迁移只增环境字段和独立发布入口表，旧环境地址为空，旧发布无入口记录。
3. 用现有 `createBackup` 暂停平台并冷备所有实际自有卷、数据库逻辑备份及配置/秘密；IdP另按既有冷备流程。校验清单与字节哈希，在随机端口和空卷恢复副本，验证原数据与旧软件，再升级副本验证迁移、SSO、原代理流量和页面。副本回退不执行删除表的 Down 迁移。
4. 副本及独立整分支审查通过后，在批准维护窗口停止原平台并对显式原目录调用 `initializeRuntime`，保留原 owner/端口/账号/环境绑定/卷。若旧包尚无登录保护HMAC，先用既有 prepareLoginProtectionSecret 的显式首次创建机制补充缺失密钥，核验owner与摘要，保持全部旧密钥不变，不重置账号。迁移成功才更新运行包记录。原Keycloak与观测卷保留。
5. 原入口只读核对新增字段默认值、旧业务行/凭证/快照及历史上下文完整、镜像及静态来源、原账号和真实SSO、双网关实际应用和原调用路径。若节点进程变化，使用原运行应用确认机制，不伪造 ACK，也不未经业务授权新增发布。
6. 软件回退保留新增数据及迁移：先冷备升级后的完整状态，确认旧软件可兼容读取后只切回旧软件，保留新增列/表。升级后若已创建入口历史或新业务数据，不能用升级前数据库覆盖；如需数据恢复，保留新数据备份，按业务记录逐项恢复并另行审阅。

状态字段分别记录 `sourceVerified`、`isolatedAcceptance`、`localInstalled`、`productionAcceptance`，未实际验证不得设为 true。生产验收保持 false。
