# 重复数据库迁移优化与验证

日期：2026-11-18。基线为main `da230b6`；分支从包含上一轮状态记录的`13277d6`开始，二者产品及测试源码相同。方案仅改变显式选入的测试数据库准备，不改变产品、依赖、检查脚本、CI、超时、断言或并发设置。

## 实现与边界

每个测试类拥有一个延迟创建的临时模板，使用当前程序集真实执行全部EF迁移，关闭模板连接并禁止重新连接。普通内容测试克隆独立数据库，仍各自创建用户、种子数据、启动HTTP服务、真实登录和执行原断言。模板、克隆和服务按所有权释放；初始化失败传播原错误并清理，清理也失败时保留两个异常。显式保留数据库和环境保留模式继续有效。

无跨类、跨进程、跨运行持久缓存；新实例使用新数据库身份，记录程序集与迁移列表指纹。迁移生成的系统元数据也会复制，因此时钟水位、新鲜度、安全准入、权限撤销、初始化、迁移回执及故障/期限测试继续使用原始路径。具体设计见[设计说明](../superpowers/specs/2026-11-18-migration-template-design.md)。

## 私有逐次诊断

私有副本交替轮换三种准备策略，每种6次，均检查迁移历史已完整应用。准备计时含创建目标空库或克隆，不含后续验证、销毁和HTTP启动。结果不替代业务集成检查。

| 准备方式 | 平均毫秒 | 最小—最大毫秒 |

| 创建空库并真实MigrateAsync | 1041.921 | 721.009—1467.542 |
| 复制已迁移模板 | 37.521 | 31.213—57.359 |
| 执行缓存的EF生成SQL（仅私有探索） | 413.885 | 341.136—477.346 |

首次模板准备3598.583毫秒，脚本生成773.087毫秒，不能从成本中省略。复制的单次准备时间下降约96.4%，这个比例排除首次模板准备，且不含其他测试工作；绝不能视为完整测试或GitHub任务的提速比例。缓存SQL没有进入正式实现，也没有获得全量资格。

## 隔离与失败证据

新增回归覆盖：数据库结构/约束/索引/触发器/函数及迁移历史等价、默认空库、并发只迁移一次、跨克隆数据隔离、真实HTTP登录、源模板禁止连接、克隆与销毁竞争、不同实例不复用身份、失败迁移清理和禁止克隆、明确保留模式、服务/种子初始化失败清理与原错误保留。

首次未实现版本7失败/1通过；首次实现8项通过。独立审查发现保留模式误报和初始化失败遗漏清理，新增3项回归先全部失败，修复后全部11项通过；另在私有副本启用`WEBAPI_TEST_RETAIN_DATABASES=1`，同样11项全部通过。保留模式的容器也仅由本轮所有权脚本在诊断结束后清理。原失败、每轮日志和源码哈希保存在本机`deliverables/migration-template-20261118/`，不改写为通过。样本、私有诊断、完整本机与GitHub运行必须分别记录；只在完整本机及四项GitHub必需检查均通过后合并。
