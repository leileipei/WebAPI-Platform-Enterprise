# 跨环境 API 发布晋级运行手册

## 启用与日常使用

原项目默认 `Legacy`，保留原发布流程。管理员明确选择同项目的非生产来源和生产目标，确认目标已经通过既有审批发布真实基线、当前节点全确认后，才启用 `PromotionRequired`。无基线的目标不会绕过预检；先用 Legacy 建立基线，再启用连接。

环境管理配置各环境独立的 Gateway 对外地址、内部地址和 API 路径前缀。Destination 保存业务上游地址。URL 为环境元数据，DNS、TLS、代理或负载均衡需由实际部署单独提供；保存 URL 不会开通域名。晋级保留目标入口，不能把来源入口当生产地址。

1. 来源发布成功且所有来源节点确认当前配置后，从发布详情生成不可变制品。
2. 本次来源全节点确认后实际执行接口功能、集成和契约测试，再分别登记人工证据；测试结束时间不得早于本次部署全节点确认，历史不符证据也不能沿用；报告可单独上传为 PDF/TXT（最大10 MiB）。上传报告本身不会登记测试结果。
3. 申请测试验收，由有来源范围权限的独立人员核对。申请人不能验收自己的申请，管理员同样受此限制。
4. 从已验收制品创建晋级，明确选择目标 Route、Cluster、策略槽位和应用凭证、API授权。来源凭证不会自动复制。纯 JWT 应用可明确选择空 API Key 集合，但必须有合法目标 JWT 应用映射和 API 授权；ApiKey 路由仍需有效目标凭证。共用应用必须明确确认影响，并保留基线其他业务需要的凭证和授权。
5. 核对环境差异、人工上游健康及风险评审，运行服务器预检。修改映射、基线、入口、连接、来源验收或相关资源后，重新核对，不能沿用旧批准。
6. 提交正式生产审批，两名独立审批者按冻结席位依次处理；正式发布人执行下发。
7. 全节点 ACK 只表示配置已应用。独立生产验证人还需实际执行并登记入口连通性、认证授权和关键业务调用。申请人和实际发布人不能承担本次生产验证。只有当前三类有效证据齐全且通过才完成交付。

409/412 保留当前表单输入，先读取最新资料、明确采用最新修订并重新核对。权限撤销后受限资料和操作会清空；受限计数不表示零风险。完成的历史交付与当前节点事实分别展示。

## 下发失败、恢复与回滚

部分 ACK 或超时不会伪造全部节点成功。查看正式发布详情的冻结节点与当前节点，记录各自实际版本和序列。现有失败重试复用已批准的目标快照，产生新的下发序列和恢复记录，并通过原正式发布追溯制品；不能用重试构造任意新内容。

生产验证失败保留失败证据，系统不会自动回滚。实际处置后重新登记当前上下文，或从现有发布详情创建指向此前目标快照的回滚申请，经过原生产审批后执行。回滚全确认才记为已回滚；目标对外入口不会因配置快照回滚而自动还原。若实际配置或入口已改变，不能复用旧验证完成本次交付。

排队后仍会重新校验发布身份、连接、资源和来源验收。撤销来源验收会取消尚未真正下发的关联申请；已应用的节点事实不会被改写成从未发生。

## 备份、恢复与升级

维护升级先确认当前固定镜像和原数据，再冷备 PostgreSQL、受控报告、LKG、观测历史与私有配置卷。原 SSO、登录保护、缓存和通知凭证保持原值。数据库、报告文件及摘要关联必须一起恢复到新的隔离项目并实际登录下载核对，不以有压缩包代替恢复验证。

双环境验收夹具的生产节点额外使用固定 `delivery-secrets`、`delivery-lkg-a`、`delivery-lkg-b` 卷；备份同时暂停来源及目标节点，记录明确的部署元数据，恢复仅允许新的 UUID、归属标签和端口。所有清理均验证资源归属，禁止删除共享资源。

升级后新增的晋级、验收和验证事实不能被旧数据库覆盖。候选异常优先修复前进；旧软件兼容性需要对当前实际数据独立验证，不承诺无条件降级，不执行破坏性 Down/drop 迁移。保留维护前冷备，用于隔离排查和灾难恢复，不用于日常覆盖新事实。

## 验证入口与证据界限

配置 `WEBAPI_NODE` 和 `WEBAPI_PNPM` 为本机已安装运行时；浏览器验收还需 `WEBAPI_NODE_RUNTIME`、`WEBAPI_CHROMIUM_EXECUTABLE`。`scripts/check-promotion.sh domain|integration|gateway|console` 执行各回归。默认 Docker 网络池已满时，可明确指定未使用的私有 `WEBAPI_CONTRACT_TEST_SUBNET=10.249.x.0/24`，工具保留原默认且由 Docker 拒绝重叠，不清理他人的网络。

`e2e|faults|browser <完整固定SHA>` 均运行一个完整、独立的双环境验收，包含真实浏览器、故障和受控报告冷备恢复。三个名称为同一完整入口，避免拆分后丢失真实部署上下文；完成一次完整运行即可取得三部分证据。固定源码通过 `git archive` 构建，核对实际镜像和应用逐文件摘要；人工逐张检查1440/1280截图后才封档。`verify <证据目录>` 校验文件摘要、实际节点/请求/身份/验证/恢复记录和清理结果。

隔离项目使用合成业务、验收账号和人工证据登记；本机 TLS 使用单独证书和代理。这能验证软件行为，不能替代企业 DNS/TLS/LB、企业上游、生产容量或 HA 验收。`sourceVerified`、`isolatedAcceptance`、`localInstalled`、`productionAcceptance` 分别记录，原4192实际升级并复验后才标本机已安装。
