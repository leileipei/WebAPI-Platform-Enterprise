# 凭证治理的独立见证接入

本文记录独立分支上的可插拔实现与控制面接入。公开租约签发返回 `503 security_evidence_unavailable`，治理快照激活处于关闭状态。普通凭证创建、撤销与轮换沿用主线流程。签名公钥、TLS 客户端证书和见证身份由独立运维配置并验收。

## 独立来源

- `IndependentEvidenceHttpClient` 向分别配置的时间与历史来源提交同一个规范 JSON 挑战。现有 `IndependentEvidenceSession` 固定来源、签名密钥、用途及节点实例，复核时间范围与历史回复。两种来源的回复上限各为 32 KiB。
- `GovernanceJournalHttpWitness` 使用独立部署的 HTTPS 端点。客户端证书由调用方提供并持有，服务端校验证书、授权写入身份并限制可访问的账本。客户端校验平台 TLS 服务端证书及另行固定的响应签名公钥。
- HTTP 连接上限为 3 秒，请求及响应读取合计上限为 5 秒，响应头上限为 16 KiB。固定端点禁止重定向。写入见证请求和回复各限 512 KiB，可恢复材料解码后限 256 KiB。
- 宿主可显式调用 `IndependentGovernanceWitnessClients.Create` 组合这些客户端。缺省返回关闭状态。启用后要求完整固定来源、账本代次和 P-256 公钥，写入使用独立身份的 TLS 客户端证书。只读历史和持久写入可使用同一历史信任根，时间签名使用专用密钥。现有生产宿主的默认服务注册保持关闭。

## 有序提交合同

每个 `GovernanceJournalId` 有单独固定的 authority 与 generation，供同一控制面的跨环境写入使用。操作编号及其内容永久绑定。并发写入以已经确认的序号和头为前置条件，每个账本最多有一项未完成准备。见证须独立持久保存已确认头、未完成意图、可恢复材料以及每项已确认操作的确切位置，支持按操作编号重查。

`observe` 返回当前确认位置与准备意图，并按需要返回指定操作的历史确认。`prepare` 以条件更新方式持久保存原操作及其前序位置。`confirm` 将同一准备意图推进到下一位置，保留操作确认并清除准备意图。重试只接受完全相同的操作。来源不确定或回复丢失时重新 `observe`。未完成准备不能超时后直接丢弃或由另一个操作替换。后续签发仍需与见证侧准备及租约预留共享栅栏。

同一固定的见证端点支持 `reserveAllowLease` 的客户端合同。请求绑定预期已确认位置、账本代次、环境、节点实例，以及租约的标识、摘要和有效期。客户端核对独立签名、请求摘要、账本位置和原预留内容，要求确认预留已持久保存且当时没有待确认写入。服务端必须在与 `prepare` 相同的写入顺序中原子核对位置和待处理状态，以可信时间检查期限，并按租约标识保存精确内容和期限。重试沿用相同租约标识及内容。签发仍须另外取得可信时间及完整历史，在结果不明时保持拒绝。

## 数据库与控制面入口

迁移 `20261118130000_CredentialGovernanceJournal` 将只追加账本加入托管迁移和独立 SQL 安装路径。两条路径都核验主线迁移前缀、账本结构和写保护。迁移创建空账本，待控制面显式绑定独立见证。登记在数据库写锁内校验当前会话和平台权限，核对完整结构指纹，并要求独立见证证明账本处于初始位置。重复登记会重新查询见证，只接受同一未开始写入的账本。

迁移 `20261119123000_LegacyGlobalRevocationInheritance` 区分原始撤销、封存时的撤销与后续继承。继承事件关联同一笔不可变的原始撤销。封存事件记录独立隔离证明摘要，写入时要求环境和旧节点均已停用。EF 和独立 SQL 安装器使用相同的新指纹，既有事件、迁移前缀及已批准指纹保留。

权限目录包含 `credential.revoke` 和 `credential.governance.recover`，默认授予平台管理员。即时撤销同时要求目标范围的写权限。既有实例按已批准的维护窗口执行 `--seed-catalog` 刷新目录。[权限目录运维流程](release-promotion-runbook.md)

标准宿主读取 `CredentialGovernance` 配置。显式启用时固定 `TimeEvidence`、`HistoryEvidence`、`GovernanceJournal` 和 `JournalId`，并从 `WriterCertificateFile` 加载单独配置的客户端证书。在 Linux 和 macOS 上，以绝对路径挂载写入身份专用的无口令 PKCS#12，文件权限为 0400 或 0600。程序只在授权操作需要见证时加载证书。内嵌宿主也可以通过 `AddWitnessedCredentialGovernance` 注册已有证书。运行中的撤销需要宿主提供能复核对应部署与受控入口的 `ICredentialRevocationCoverage`。在缺少该证据时，写入返回 503。控制面在等待写锁后重新核对会话及操作授权。

- `POST /api/v1/credential-governance/journal/enroll` 显式绑定当前独立账本。
- `POST /api/v1/credential-governance/journal/recover` 按已准备的原命令恢复，并重新检查权限与证据。
- `POST /api/v1/credentials/{id}/revoke` 接受有效的 `If-Match`、`Idempotency-Key` 和预定义理由 `compromised`、`owner_request`、`credential_retired` 或 `policy_change`。理由码可进入见证材料。
- `POST /api/v1/credentials/{id}/formal-rotation/preview` 接受 `If-Match`、目标环境、新凭证有效期、重叠窗口及硬截止。要求目标范围的 `credential.manage` 和 `credential.revoke`，只读核验凭证与账本。
- `GET /api/v1/credential-revocations/{operationId}` 复核所有记录环境的权限后返回本地账本与节点目标。独立复核和全部入口覆盖仍待联合验证时，公开状态为 `Unconfirmed`。

三种调用都发送 POST，使用小驼峰属性名、按序排列的对象键、无多余空白的 UTF-8 JSON。字段集合和顺序以 `GovernanceJournalProtocol` 的规范编码为准。每次请求生成新的 32 字节随机数。响应签名绑定包含随机数的整个请求摘要，使用 P-256/SHA-256 和 64 字节 IEEE P1363 签名，公钥使用 DER SPKI。签名与公钥按规范 Base64 表示。恢复材料使用无填充的规范 Base64URL。材料须能重建经授权的操作、完整环境范围、前后账本位置及精确写入结果，且不含凭证明文、秘密回执或签名私钥。

| 阶段 | 本地处理 |
| --- | --- |
| 见证已准备，本地在前序位置 | 以持久准备材料原子提交确切变更、下一位置与待确认标记。 |
| 本地已提交，见证仍准备 | 复验实际变更、位置与标记，按同一意图确认。 |
| 见证已确认，本地仍待标记 | 复验实际变更及该操作的独立确认，随后清除待确认标记。 |
| 见证已确认，本地回退 | 阻断并要求可信恢复材料，保持见证高水位。 |
| 另一操作待恢复，旧操作重试 | 匹配原操作及其实际写入后可返回原结果。待恢复操作继续保持。 |

`PostgresGovernanceWriterFence` 独占物理数据库连接，在事务提交和回滚之间持有与现有授权命令兼容的写入锁。每个事务重新检查服务端会话身份与锁归属。接入使用直连或会话固定的数据库端点。`PostgresGovernanceCommitStore` 在同一物理事务内保存实际写入和待确认记录，确认凭据另行追加。读取时验证安装的固定账本根与顺序，复核最近操作以及指定的重放操作。

`PostgresCredentialRevocationService` 覆盖环境绑定凭证与全部受影响范围可核验的全局凭证。首次写入要求专门撤销权限、`If-Match`、幂等键及理由。环境绑定凭证须指定其绑定环境。全局凭证从已核验的完整工件清单确定范围，请求中的环境字段须为空。准备与提交均核对确切发布、快照哈希、所有启用实例、当前租约及入口保护证据。宿主的 `ICredentialRevocationCoverage` 在持锁事务中只查询已经验证的本地证据。提交回执保持 `Unconfirmed`，节点传播状态仍依赖运行证明。恢复会重新核对原授权和准备时的事实，权限、范围或有效证据变化时保留待处理记录。准备前还会检查当前证明是否覆盖见证请求的时间预算。

全局范围核对包含活跃授权、应用映射、冻结候选和历史快照。通过全部范围授权与运行证明后，一笔不可变的撤销操作和所有受影响环境的事件、墓碑、目标、发件箱、审计及见证待确认记录在同一 PostgreSQL 事务中落账。工作配置的 `Revoked` 状态继续按原发布规则生效。旧环境绑定操作保留原见证材料格式。

发布、重试和回滚在更新期望版本和发件箱前检查最终快照。涉及已即时撤销的全局凭证时，要求 2.4、匹配当前安全账本的版本与策略，以及目标环境完整的撤销记录。相应应用的授权新增、续期或迁移也要求目标环境已有完整撤销记录。

新增环境在创建事务中继承适用的全局撤销并记录 2.4 安全下限。重新启用受影响的环境需要宿主通过 `ICredentialArchivedIngressWitness` 提供与当前范围匹配的封存证明。范围绑定账本位置、旧发布与快照、入口地址修订、历史节点与租约记录。旧节点须全部停用，可能有效的租约须越过时钟偏差余量。独立证明还须确认旧进程、外部直连和缓存或本地快照已无法恢复流量。缺少或变更证明时返回 409。控制面在同一事务中继承撤销、保留原发布序号、清除旧下发指针，并退役封存前的节点。历史快照原始字节保留。上级重新启用会检查仍为启用状态的受影响子环境，避免绕过单独核验。

已证实无入口的封存环境可参加同一笔全局撤销。回执用 `SealedNoIngressAtCommit` 表示操作提交时已核验的封存状态。该状态独立于运行节点的确认。未来环境使用由原撤销派生的账本记录，原操作回执与授权范围保持冻结。控制面拒绝停用范围的配置下发，工作进程只投递仍匹配当前指针的发布。实际入流仍依赖独立验证的安全状态。

## 网关请求验证

`IGovernanceAdmissionStateProvider` 允许宿主按具体路由代际提供进程内的可信安全状态，缺少状态时治理认证请求拒绝。启用后以当前租约、环境绑定、撤销墓碑、路由方法和授权修订作出准入决定。测试在两个隔离实例中使用真实 PostgreSQL 读取的墓碑和测试签名。实例漏收更新时仍受已有租约的硬边界约束。该测试的密钥、来源和网关状态仅属于隔离环境。

## 正式轮换硬截止

正式轮换预检在数据库写锁内复核会话、双权限、凭证和环境绑定、`If-Match`、已发布的 2.4 快照及全部当前节点实例。返回截止时间、目标、最后有效凭证风险和预览摘要。`IFormalRotationLeaseHorizonWitness` 须提供绑定同一独立账本位置的完整租约范围及可信时间。核验包括已退役实例的不可变发行记录。缺少可信证明、存在待确认写入或现有租约跨越截止时拒绝。实际登记需要重新取得现行证据，并在独立见证的写入事务中与租约预留一起复核期限。

`RotationLeaseDeadlinePolicy` 的准备判定要求完整的可能有效租约范围，并核对最晚允许到期时间。续签上限由硬截止减去最大时钟偏差、拟定租约到期和可信时间有效期三者取最早。时间与传输、应用预算不足时停止签发允许流量的租约。偏差取所有可能仍有效实例的可证实上界。既有发行记录无法证明更小偏差时采用协议上限两秒。登记硬截止及在截止前全部确认的中止都需要纳入见证顺序；半完成中止不解除截止。

启用治理还需要正式轮换确认、登记与执行，独立租约签发、网关续签及重新发布 2.4。跨 PostgreSQL 与见证的准备、写入和签发预留需共用可验证的隔离机制。恢复后的业务下发需要独立核验数据库和见证账本的连续性。实际独立服务、旧写入者及旧签名能力的隔离、两个受控网关联合验证属于启用条件，覆盖单侧恢复、旧入口隔离和无处理器的硬截止。
