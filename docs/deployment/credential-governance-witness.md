# 凭证治理的独立见证接入

本文记录独立见证协议、标准宿主配置和撤销回执判定。签名公钥、TLS 客户端证书和见证身份由独立运维配置并验收。默认租约入口返回 `503 security_evidence_unavailable`。治理 2.4 需要明确启用并接入经核验的独立来源。

## 独立来源

- `IndependentEvidenceHttpClient` 向分别配置的时间与历史来源提交同一个规范 JSON 挑战。现有 `IndependentEvidenceSession` 固定来源、签名密钥、用途及节点实例，复核时间范围与历史回复。两种来源的回复上限各为 32 KiB。
- `GovernanceJournalHttpWitness` 使用独立部署的 HTTPS 端点。客户端证书由调用方提供并持有，服务端校验证书、授权写入身份并限制可访问的账本。客户端校验平台 TLS 服务端证书及另行固定的响应签名公钥。
- HTTP 连接上限为 3 秒，请求及响应读取合计上限为 5 秒，响应头上限为 16 KiB。固定端点禁止重定向。写入见证请求和回复各限 512 KiB，可恢复材料解码后限 256 KiB。
- 宿主可显式调用 `IndependentGovernanceWitnessClients.Create` 组合这些客户端。缺省返回关闭状态。启用后要求完整固定来源、账本代次和 P-256 公钥，写入使用独立身份的 TLS 客户端证书。只读历史和持久写入可使用同一历史信任根，时间签名使用专用密钥。现有生产宿主的默认服务注册保持关闭。

## 有序提交合同

每个 `GovernanceJournalId` 有单独固定的 authority 与 generation，供同一控制面的跨环境写入使用。操作编号及其内容永久绑定。并发写入以已经确认的序号和头为前置条件，每个账本最多有一项未完成准备。见证须独立持久保存已确认头、未完成意图、可恢复材料以及每项已确认操作的确切位置，支持按操作编号重查。

`observe` 返回当前确认位置与准备意图，并按需要返回指定操作的历史确认。`prepare` 以条件更新方式持久保存原操作及其前序位置。`confirm` 将同一准备意图推进到下一位置，保留操作确认并清除准备意图。重试只接受完全相同的操作。来源不确定或回复丢失时重新 `observe`。未完成准备不能超时后直接丢弃或由另一个操作替换。后续签发仍需与见证侧准备及租约预留共享栅栏。

同一固定的见证端点支持 `reserveAllowLease` 的客户端合同。请求绑定预期已确认位置、账本代次、环境、节点实例，以及租约的标识、摘要和有效期。客户端核对独立签名、请求摘要、账本位置和原预留内容，要求确认预留已持久保存且当时没有待确认写入。服务端必须在与 `prepare` 相同的写入顺序中原子核对位置和待处理状态，以可信时间检查期限，并按租约标识保存精确内容和期限。重试沿用相同租约标识及内容。签发仍须另外取得可信时间及完整历史，在结果不明时保持拒绝。

## 数据库与控制面入口

迁移 `20261118130000_CredentialGovernanceJournal` 将只追加账本加入托管迁移和独立 SQL 安装路径。两条路径都核验主线迁移前缀、账本结构和写保护。迁移创建空账本，待控制面显式绑定独立见证。登记在数据库写锁内校验当前会话和平台权限，核对完整结构指纹，并要求独立见证证明账本处于初始位置。重复登记会重新查询见证，只接受同一未开始写入的账本。

迁移 `20261119123000_LegacyGlobalRevocationInheritance` 区分原始撤销、封存时的撤销与后续继承。继承事件关联同一笔不可变的原始撤销。封存事件记录独立隔离证明摘要，写入时要求环境和旧节点均已停用。EF 和独立 SQL 安装器使用相同的新指纹，既有事件、迁移前缀及已批准指纹保留。

权限目录包含 `credential.revoke` 和 `credential.governance.recover`，默认授予平台管理员。即时撤销同时要求目标范围的写权限。既有实例按已批准的维护窗口执行 `--seed-catalog` 刷新目录。[权限目录运维流程](release-promotion-runbook.md)

标准宿主读取 `CredentialGovernance` 配置并固定账本和独立签名身份。控制面在等待写锁后重新核对会话及操作授权。运行撤销要求受控入口证据，配置和协议见文末。内嵌控制面可通过 `AddWitnessedCredentialGovernance` 注册已有证书和注入显式证明来源。

- `POST /api/v1/credential-governance/journal/enroll` 显式绑定当前独立账本。
- `POST /api/v1/credential-governance/journal/recover` 按已准备的原命令恢复，并重新检查权限与证据。
- `POST /api/v1/credentials/{id}/revoke` 接受有效的 `If-Match`、`Idempotency-Key` 和预定义理由 `compromised`、`owner_request`、`credential_retired` 或 `policy_change`。理由码可进入见证材料。
- `POST /api/v1/credentials/{id}/formal-rotation/preview` 接受 `If-Match`、目标环境、新凭证有效期、重叠窗口及硬截止。要求目标范围的 `credential.manage` 和 `credential.revoke`，只读核验凭证与账本。
- `GET /api/v1/credential-revocations/{operationId}` 对原操作的所有环境重新校验会话和撤销权限，并以 `Cache-Control: no-store` 返回落账事实、目标及按当前证据计算的传播状态。

三种调用都发送 POST，使用小驼峰属性名、按序排列的对象键、无多余空白的 UTF-8 JSON。字段集合和顺序以 `GovernanceJournalProtocol` 的规范编码为准。每次请求生成新的 32 字节随机数。响应签名绑定包含随机数的整个请求摘要，使用 P-256/SHA-256 和 64 字节 IEEE P1363 签名，公钥使用 DER SPKI。签名与公钥按规范 Base64 表示。恢复材料使用无填充的规范 Base64URL。材料须能重建经授权的操作、完整环境范围、前后账本位置及精确写入结果，且不含凭证明文、秘密回执或签名私钥。

| 阶段 | 本地处理 |
| --- | --- |
| 见证已准备，本地在前序位置 | 以持久准备材料原子提交确切变更、下一位置与待确认标记。 |
| 本地已提交，见证仍准备 | 复验实际变更、位置与标记，按同一意图确认。 |
| 见证已确认，本地仍待标记 | 复验实际变更及该操作的独立确认，随后清除待确认标记。 |
| 见证已确认，本地回退 | 阻断并要求可信恢复材料，保持见证高水位。 |
| 另一操作待恢复，旧操作重试 | 匹配原操作及其实际写入后可返回原结果。待恢复操作继续保持。 |

`PostgresGovernanceWriterFence` 独占物理数据库连接，在事务提交和回滚之间持有与现有授权命令兼容的写入锁。每个事务重新检查服务端会话身份与锁归属。接入使用直连或会话固定的数据库端点。`PostgresGovernanceCommitStore` 在同一物理事务内保存实际写入和待确认记录，确认凭据另行追加。读取时验证安装的固定账本根与顺序，复核最近操作以及指定的重放操作。

`PostgresCredentialRevocationService` 覆盖环境绑定凭证与全部受影响范围可核验的全局凭证。首次写入要求专门撤销权限、`If-Match`、幂等键及理由。环境绑定凭证须指定其绑定环境。全局凭证从已核验的完整工件清单确定范围，请求中的环境字段须为空。准备与提交均核对确切发布、快照哈希、所有启用实例、当前租约及入口保护证据。宿主的 `ICredentialRevocationCoverage` 在持锁事务中只查询已经验证的本地证据。提交回执保持 `Unconfirmed`，节点传播状态仍依赖运行证明。恢复会重新核对原授权和准备时的事实，权限、范围或有效证据变化时保留待处理记录。准备前还会检查当前证明是否覆盖见证请求的时间预算。

全局范围核对包含活跃授权、应用映射、冻结候选和历史快照。通过全部范围授权与运行证明后，一笔不可变的撤销操作和所有受影响环境的事件、墓碑、目标、发件箱、审计及见证待确认记录在同一 PostgreSQL 事务中落账。工作配置的 `Revoked` 状态继续按原发布规则生效。旧环境绑定操作保留原见证材料格式。

发布、重试和回滚在更新期望版本和发件箱前检查最终快照。涉及已即时撤销的全局凭证时，要求 2.4、匹配当前安全账本的版本与策略，以及目标环境完整的撤销记录。相应应用的授权新增、续期或迁移也要求目标环境已有完整撤销记录。

新增环境在创建事务中继承适用的全局撤销并记录 2.4 安全下限。重新启用受影响的环境需要宿主通过 `ICredentialArchivedIngressWitness` 提供与当前范围匹配的封存证明。范围绑定账本位置、旧发布与快照、入口地址修订、历史节点与租约记录。旧节点须全部停用，可能有效的租约须越过时钟偏差余量。独立证明还须确认旧进程、外部直连和缓存或本地快照已无法恢复流量。缺少或变更证明时返回 409。控制面在同一事务中继承撤销、保留原发布序号、清除旧下发指针，并退役封存前的节点。历史快照原始字节保留。上级重新启用会检查仍为启用状态的受影响子环境，避免绕过单独核验。

已证实无入口的封存环境可参加同一笔全局撤销。回执用 `SealedNoIngressAtCommit` 表示操作提交时已核验的封存状态。该状态独立于运行节点的确认。未来环境使用由原撤销派生的账本记录，原操作回执与授权范围保持冻结。控制面拒绝停用范围的配置下发，工作进程只投递仍匹配当前指针的发布。实际入流仍依赖独立验证的安全状态。

## 网关请求验证

`IGovernanceAdmissionStateProvider` 允许宿主按具体路由代际提供进程内的可信安全状态，缺少状态时治理认证请求拒绝。启用后以当前租约、环境绑定、撤销墓碑、路由方法和授权修订作出准入决定。测试在两个隔离实例中使用真实 PostgreSQL 读取的墓碑和测试签名。实例漏收更新时仍受已有租约的硬边界约束。该测试的密钥、来源和网关状态仅属于隔离环境。

## 正式轮换硬截止

正式轮换预检在数据库写锁内复核会话、双权限、凭证和环境绑定、`If-Match`、已发布的 2.4 快照及全部当前节点实例。返回截止时间、目标、最后有效凭证风险和预览摘要。`IFormalRotationLeaseHorizonWitness` 须提供绑定同一独立账本位置的完整租约范围及可信时间。核验包括已退役实例的不可变发行记录。缺少可信证明、存在待确认写入或现有租约跨越截止时拒绝。实际登记需要重新取得现行证据，并在独立见证的写入事务中与租约预留一起复核期限。

`RotationLeaseDeadlinePolicy` 的准备判定要求完整的可能有效租约范围，并核对最晚允许到期时间。续签上限由硬截止减去最大时钟偏差、拟定租约到期和可信时间有效期三者取最早。时间与传输、应用预算不足时停止签发允许流量的租约。偏差取所有可能仍有效实例的可证实上界。既有发行记录无法证明更小偏差时采用协议上限两秒。登记硬截止及在截止前全部确认的中止都需要纳入见证顺序；半完成中止不解除截止。

## 2026-11-19 正式轮换与运行门禁

- 可先在凭证创建请求中指定 `environmentId`，取得同应用同环境的替换凭证。此操作沿用一次性 Secret 回执。包含该凭证编号的预检将其修订、有效期和环境纳入摘要。确认使用 `POST /api/v1/credentials/{id}/formal-rotation/confirm`，提交预检窗口、摘要、`confirmAutomaticRevocation: true` 和预定义理由，并附上 `If-Match`、`Idempotency-Key`。轮询 `GET /api/v1/credential-rotations/{id}` 可查看排程或已落账撤销。
- 迁移 `20261119140000_FormalCredentialRotation` 增加只追加的排程表。确认在当前写事务中重新核对原凭证、替换凭证、权限和预检摘要。独立见证使用 `prepareFormalRotation`，在其持久化顺序内复核全环境租约期限并登记截止。Worker 从同一账本恢复待确认记录，在数据库和独立见证均达到硬截止后写入旧凭证墓碑、目标、发件箱和审计。重叠结束时保留旧凭证的原运行状态。回执的 `RevocationRecorded` 表示撤销事实已落账。网关传播仍按独立目标证明核对。
- 2.4 使用显式环境名单，并通过既有审批和全量入口门槛。首次转换须冻结仍在运行的全部 API。构建、下发和确认复核冻结目标、路由授权修订、账本和实例。已确认的当前发布可以配合更新后的同代次账本恢复。新的待发布工件须匹配冻结时的安全状态。治理恢复仍需根据当前权限重新构建历史业务配置。
- `PostgresGovernanceRecoveryContinuity` 要求在实际下发或签发事务中比对独立账本和目标环境历史。配套的 `RecoveryHistory` 来源固定独立身份、公钥和 HTTPS 端点。受控部署须在数据库恢复范围之外保留启用状态、账本身份及见证固定项。证据缺失、双方待确认或任一历史不一致时停止下发。控制面与 Worker 需要为同一部署注入相同的连续性和发布范围。
- 租约签发还需要宿主注入 `SecurityLeaseEvidenceSources`，分别校验可信时间和历史，再让独立见证精确预留租约。签名在本地不可变发行事实提交后才返回。网关可通过 `AddWitnessedGatewaySecurity` 注入独立时间、历史来源和签名公钥，在当前实例重新获取并验证安全状态。受保护请求在有效状态缺失或过期时返回 503。当前墓碑和允许租约均已核验时，旧凭证返回 401。

实际启用仍待独立服务、旧写入者及旧签名能力隔离、受控外部入口证明，以及真实双网关的联合验证。原安装环境和历史工件保留。完整治理还包含历史环境的可信初始化、正式轮换的人工完成与中止、逐实例新钥成功证明、控制台流程和按当前权限审批重建的 2.4 业务回滚。

## 2026-11-19 人工轮换与治理交付

- 正式轮换的 `complete` 和 `abort` 使用回执修订、幂等键、明确理由和当前会话。两个动作都重新核验旧钥及替换钥的管理和撤销权限。独立见证以 `prepareFormalRotationDecision` 对确切决定排序，其可信时间上界须严格早于硬截止。异常断点的恢复通过 `observeFormalRotationDecision` 取回专用准备证据。只有带原决定和可信上界的独立记录可支持补写。迁移 `20261119150000_FormalRotationDecision` 追加决定及其意图哈希投影，恢复连续性核验与见证日志的对应关系。
- 网关可用 `IFormalRotationRequestProofSink` 采集 2.4 实例的请求证明。只记录经授权、实际完成、最终状态 200–399 且无中断和传输故障的请求。控制面从 `IFormalRotationRequestProofWitness` 获取已认证的记录，按当前发布、授权、实例和租约复核。全部实例证实后允许人工撤旧。中止先落账撤销替换钥，等待全部冻结目标的有效签名确认。独立见证须在硬截止前接受完整中止，方可解除本排程的截止限制。目标替换或证据不齐时继续执行原截止。控制台分别展示登记、实例证明、中止待确认和撤销落账。
- 历史环境预览与确认使用 `ILegacyEnvironmentHistoryReader` 校验受支持迁移来源、部署及恢复清单、全部已知实例、原始快照和停写范围。当前权限和预览摘要复核后，共事务写入 `VerifiedLegacyNetwork`、安全初态及审计。未知或证据矛盾的环境停止旧快照投递。仅当独立环境历史承认该初态时才可继续租约签发。
- 治理回滚从可等价重建的已发布 2.4 工件读取历史业务配置，保留当前授权、凭证及账本，生成新配置版本和部署序列。提交、批准、排队、构建与节点交付复核对应门禁。路由身份、访问策略或原历史工件无法核验时停止。晋级使用目标环境最终版本路由、明确的路由方法授权、目标环境凭证与现有独立审批。路由方法授权是一项工作配置，经相应 2.4 发布和节点确认后生效。冻结版本、目标和安全状态都参与后续下发检查。

独立服务、历史清单及两个网关的真实环境验收仍待接入。隔离验证使用独立数据库、控制面和签名测试替身。正式运行需要为控制面、Worker 和网关注入与同一治理部署匹配的证据来源及发布范围。


## 2026-11-20 标准宿主配置

在环境变量中以双下划线连接配置层级，例如用 `CredentialGovernance__Enabled` 配置 `CredentialGovernance:Enabled`。在各进程显式启用，发布环境名单由控制面与 Worker 使用相同的环境 UUID。三种宿主在启动时固定信任配置，按同一账本代次部署并重启以应用配置变更。

| 宿主 | 配置 |
| --- | --- |
| 控制面和 Worker | `CredentialGovernance:Enabled=true`。配置相同的 `JournalId:AuthorityId`、`JournalId:Generation`、`Environments` 和下列外部见证角色。各宿主以 `WriterCertificateFile` 指定已授权的客户端身份。 |
| 控制面 | `Security:Signing:KeyId`、`Security:Signing:PrivateKeyFile` 配置租约签发者，`Security:TrustedKeys` 固定明确仍受信任的租约公钥。部署覆盖、历史、日志、完成证明和签发者分别使用约定的信任根。 |
| Gateway | `CredentialGovernance:Enabled=true`，配置 `TimeEvidence`、`HistoryEvidence`、`CredentialGovernance:LeaseVerificationKeys`。后者以签发 KeyId 为键，值为规范 Base64 P-256 DER SPKI 公钥。`Gateway:ControlPlaneUrl` 使用 HTTPS。要启用完成证明交付，再配置 `RotationProofs`、`JournalId` 和此网关专用的 `RotationProofCertificateFile`。 |

每个角色均含 `Endpoint`、`SourceId`、`KeyId`、`SubjectPublicKeyInfoBase64`。端点固定于 HTTPS，响应校验固定身份、响应签名和请求摘要。Linux 和 macOS 以专用绝对路径挂载无口令 PKCS#12，文件权限为 0400 或 0600。私钥各自保存在签发者、客户端身份或独立见证的持有边界。活跃租约签发公钥也参与独立密钥冲突校验。

| 角色 | 证明边界 |
| --- | --- |
| `TimeEvidence`、`HistoryEvidence` | 通过现有随机挑战验证确切节点、实例、账本安全状态和新鲜时间。控制面签发和网关准入分别请求。 |
| `GovernanceJournal`、`RecoveryHistory` | 使用固定账本代次复核有序写入、租约预留、已确认位置与当前环境历史。缺少证据时关闭相应 2.4 投递及签发。 |
| `DeploymentEvidence` | 由独立部署权威提供运行入口覆盖、停用封存、全局凭证历史枚举和正式轮换租约期限。 |
| `RotationProofs` | 独立服务认证 Gateway 提交者并持久保存完成证明。控制面和 Worker 查询与排程及当前运行绑定的证明。 |
| `LegacyInitializationHistory` | 独立来源提供迁移、发布、实例及恢复清单，在同一被持有的停写范围中复核。 |

### 部署证据及撤销回执

`DeploymentEvidence` 在后台通过 POST 更新内存证明。请求包含账本身份及随机数。响应绑定请求摘要，按 `GovernanceDeploymentEvidenceProtocol` 规定的域及规范 JSON 以 P-256/SHA-256 签名。请求或回复最多 512 KiB。证明快照最长有效 30 秒，运行入口自身观察时间距外层签名观察最多 5 秒且自身有效期最多 15 秒。以单调时间和本地可信时限按更早边界判定。签名、来源、内容或刷新失败后等待新的可验证证明。

运行证明对 `CredentialRunningIngressScope` 的规范摘要作独立确认。范围含环境、项目、组织、入口地址修订及摘要、治理代次和头、成功发布、快照哈希、部署序列及按节点 ID 排序的全部当前实例和节点身份。签名服务须查验受控入口及运行实例，且在声明的时间窗内保证旧进程、直接访问和其他旁路隔离。历史覆盖声明需包含完整清单和当前独立复核。租约期限须来自同一个外部账本的有序租约预留，包括丢失回复与退役实例。新期限的准备仍由独立账本原子复验。

回执的 `FullyApplied` 要求独立日志的确切操作确认和当前头有效、原落账效果完整、每个原环境入口证据新鲜、全部运行目标具备同实例的不可变操作 ACK 及有效的已接受最新租约证明。停用环境须有现行的独立封存证据，原落账状态仍展示 `SealedNoIngressAtCommit`。部分目标具备全部证明时显示 `Partial`，证据缺失时按可证实状态显示 `Unconfirmed` 或 `Pending`。实例更替后旧 ACK 继续保留为历史事实。状态查询复核原操作范围，不将后续继承环境加入回执。

### 正式轮换请求证明与历史初始化

`GovernanceEvidenceExchangeProtocol` 为 `rotation-request-proof` 和 `legacy-environment-history` 使用分开的请求及响应签名域。固定端点接收含账本、随机数和类型化范围的 POST，返回由该请求摘要绑定的规范签名响应。连接、读取和大小限制沿用见证传输。

- Gateway 经本节点独立客户端证书发送 `RotationProofs` 的 `submit`，端点依据证书限定环境、节点和允许的实例，持久保存证明后对该次请求返回签名确认。队列上限为 256 条，满载、服务不可达或进程中止时可能缺失证明，提交路径不等待网络。部署验收需覆盖正常和峰值流量下的独立证明可达性及两实例完整性。控制面和 Worker 用具备读取权限的证书发送 `observe`，独立服务返回该排程、替换凭证和当前实例范围内的证明。现有校验继续复核实际发布、路由方法、授权、请求完成结果和不可变租约。缺少证明时人工完成保持拒绝。
- `LegacyInitializationHistory` 的 `open` 仅取得已经独立停写范围的持有引用，预览也可取得该引用。主动停止旧写入者由独立授权的外部运维流程先完成。端点原子绑定环境、账本、随机持有编号和客户端身份，再返回签名的 `Held`、清单及摘要。`check` 使用新挑战核对同一栅栏及清单摘要，`release` 仅允许原持有者释放同一编号。平台在本地事务确定已提交或已回滚后释放停写。提交或回滚结果不明时返回 `legacy_initialization_fence_retained`，并保留远端持有记录。运维须按日志中的环境和持有编号、账本及客户端身份定位同一记录，核对本地事务结果后再释放。释放只有在同一编号的签名回复为 `Released` 或 `Absent` 时才算确定。`Absent` 需同时保证该编号无法因迟到的 `open` 再建立。释放回复不明时记录环境和持有编号，已提交的初始化仍按已提交处理。平台仍在本地事务复查迁移来源、发布、全部已知实例、当前权限与预览摘要。

交付验证覆盖固定 SDK 的隔离 PostgreSQL、实际宿主注册点和签名夹具。现场仍需提供独立服务、真实证书和密钥、外部入口和旧进程隔离、备份恢复记录、两台网关及实际客户端的联合验收。
