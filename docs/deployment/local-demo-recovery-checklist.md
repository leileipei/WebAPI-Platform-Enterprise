# 本机演示恢复资料核对清单

本页用于核对某次固定备份及隔离恢复材料，不证明今天已有备份或恢复已通过。早期 `webapi-enterprise-local` 演示、七个基础卷、账号和端口属于当次安装；当前实例必须按实际运行目录、owner/project、release、工具身份及备份清单确认。

## 核对源安装和备份

- 保留源码提交、镜像与依赖、`runtime.json`、`release.json` 和实际维护工具；源代码包、应用镜像、数据库备份分别记录。
- 使用与安装匹配的备份实现。当前仓库行为见[运行工具手册](local-runtime-runbook.md)，不能直接采用旧版脚本的参数或服务停止假设。
- 基础卷包括 PostgreSQL、两份 LKG、Data Protection 和观测存储；通知、缓存、报告、迁移证据、交付和阶段流水线可能扩展范围。清单应覆盖该次实际自有资源，不能按固定七卷猜测完整性。
- 秘密、回执和原始字节单独核对。恢复 Redis 缓存不替代持久业务事实；公共管理快照不包含网关原字节所需的全部校验材料。
- 备份代码结束时会尝试恢复服务，仍需记录实际恢复结果；不能将其写成始终保持停止或必然恢复成功。

物理 PostgreSQL 归档与逻辑 dump 是替代方案，不叠加导入。新业务写入后，不得用旧备份覆盖现有事实来完成普通软件回退。

## 演示凭据与身份

当前[备份辅助代码](../../scripts/runtime/sso-deployment.mjs)在存在时复制以下已知文件，并由备份清单登记：

- `demo/local-demo-api-approver.password`
- `demo/local-demo-security-reviewer.password`
- `demo/consumer-api-key`

这修正早期“不复制 demo”的结论，但不保证任意额外文件已被覆盖；必须核对所用工具版本和实际清单。一次性管理员引导密码若已合法移除，不会由备份重新生成；数据库中的密码或 API Key 摘要也不能恢复明文。已保存秘密只放私有介质，不加入源码包、截图或公共报告。

不能将原 `demo/journal.json` 的 owner 用于接管恢复项目。恢复目标使用新的独立身份，业务 ID 和历史事实由恢复数据库保留；旧实例 ACK 不能重标成新实例确认。

## 进入恢复前的条件

先满足[恢复预算与硬配额约束](local-runtime-runbook.md#恢复目前的阻断条件)。当前默认缺少真实硬配额集成，旧恢复示例不能直接使用；不能注入合成证明或删除待核对标记来推进。

目标必须为明确的全新受控项目、独立 owner、未存在目录和经核对的空闲入口。源项目、原卷、私有备份及未决证据保留。对来源覆盖、清单、原始字节、版本能力、迁移尝试和恢复状态进行核验；任一无法确认都不能算作完成。

## 可获得有效恢复条件后的核查顺序

1. 核对管理员、实际角色/Scope、组织、项目、环境、API 和调用应用；不从历史文档猜今天的账号或业务 ID。
2. 区分历史冻结审批/ACK 与当前节点实例。先确认 LKG 与目标，再按对应协议检查当前运行或新发布，不补造历史 ACK。
3. 使用授权保存的凭据验证两网关的真实业务结果，同时核对运行版本、序列与实例；成功响应不替代全部目标确认或安全准入证明。
4. 核对备份时间范围内的日志、采样 Trace、告警、处理时间线及审计。Collector 重启不补造遥测，Unknown/Partial 保持原含义。
5. 核对凭证队列、迁移证据、通知、报告与交付资源的来源和保留状态，不能将待复核材料清零后宣布成功。
6. 复核原项目仍保留，再对精确恢复项目决定清理或证据保留。`cleanupFixture` 不保证所有卷都删除，保留结果须单独说明。

本页没有安排备份、恢复、自动清理、切换或生产验收。源码中的可调用接口、隔离验证和固定安装的实际恢复能力分别判断。
