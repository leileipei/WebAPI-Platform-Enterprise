版本状态：2026-10-16，产品固定来源 `ba9031c643aeb6050e2789fa56c5f6ddba0eeee7` 的隔离验收通过。五组3717项零失败/跳过、未筛选SDK10项、UI14项及P4-01～10严格门禁通过；详见[最终报告](../evidence/work-package4/final-summary.md)。原4192未升级，第2包暂停；本说明与新公共证据属于尚未新增Git提交的交付文档。

## 本地账号登录与改密

1. 新建本地账号、全新空库安装的初始化管理员，首次登录后进入修改密码页面。此时受限会话只允许获取CSRF、查询自身、退出和改密；业务HTTP、集合查询、导出均应返回403 `password_change_required`。
2. 输入当前密码、新密码和确认密码，沿用系统当前密码长度及复杂度规则。密码保留原始字符，前后空格和Unicode组合不能由客户端擅自转换；最大1024字符。
3. 修改成功后，服务端事务提交，再签发正常会话并恢复已分配角色与数据范围。受限会话最长10分钟、非持久、不滑动；过期后重新登录。
4. 若响应丢失，使用新密码重新登录核验；不能依靠重放成功响应重新获得Cookie。Redis保护不可用返回503时，先恢复依赖，再操作。

迁移已有账号默认不强制改密，不改变原Hash、SecurityStamp、角色和Scope。SSO账号继续由IdP管理密码，没有本地改密或本地重置入口。常规登录和部署不自动改写既有管理员密码文件。

## 管理员显式重置

在“用户管理”选择本地账号并打开重置对话框，填写符合策略的临时密码。需要平台范围的 `user.manage`，并携带当前用户修订的If-Match和CSRF保护。过期修订返回412，重新加载后再确认；不同临时密码不能复用相同幂等键。

不允许重置自己的密码、SSO账号或已停用账号。具有相应权限的其他管理员可重置唯一有效本地管理员，但必须保留其角色与Scope；自助改密使用个人改密入口。重置会更新SecurityStamp并使原会话失效，目标账号重新登录后必须改密。接口、审计与公共交付材料不回显临时密码。

## 查看统计与判断完整性

在“应用 → 凭证”选择有权环境和时间窗，查看最近使用及认证通过次数；应用详情同时提供概览、监控和审计入口。UTC整小时查询最多30天，实际范围受保留天数限制。界面提供当前小时、最近24小时及7天入口；当前小时只能表示未闭合窗口。

一次计数表示冻结快照中的ApiKey认证及API授权窗口匹配通过。缓存命中、后续限流或上游失败仍计一次；内部重试不重复。无效、过期、无API权限、JWT和匿名请求不计入本项。计数以十进制字符串传输和显示，不转为JavaScript Number；统计不会增加应用或凭证业务修订，也不触发发布。

| 状态 | 操作含义 |
|---|---|
| Available | 闭合时间窗内所需节点与覆盖材料完整；数量仍只表示上述认证口径 |
| NoData | 完整覆盖且该凭证为零；可以显示零，不能反推消费方未来不会调用 |
| Partial | 观察值为下界，可能缺报、窗口尚未闭合或采集启动较晚；不能据此证明旧Key无人使用 |
| Unknown | 缺少可证明的统计覆盖；不能把未知改成零 |

`app.read`只授予业务摘要和相应可见环境的统计，不增加 `metrics.read`、`audit.read`、日志或Trace权限。最近使用从当前可见环境统计投影，不能用全局LastUsedAt泄露其他环境的活动。已超出统计保留期的历史未知保持未知。

## 双Key轮换

1. 选择旧凭证及目标环境，创建或选择有效窗口重叠的新凭证。APIKey仅在创建成功弹窗中展示一次；保存到消费方使用的秘密管理位置，关窗或离开即清除页面内存值。
2. 通过原发布中心创建发布、独立审批并发布。向导验证目标环境的相同配置版本、部署序列、PayloadHash及至少两个不同网关节点的当前实例确认。只有工作配置保存不表示新Key已可调用。
3. 消费方切换并实际验证新Key，再由操作者明确确认；向导不自动迁移消费方。刷新后需重新核验发布材料，消费方确认不会持久化为替操作者担保的事实。
4. 在有权时间窗观察新旧凭证。Partial/Unknown时明确保留缺报提示；若仍决定停用，必须打开影响预览并明确确认风险。
5. 撤销或缩短旧凭证时提交最新影响Hash和修订。其他管理员修改、授权窗口变化或自然到期可能导致409/412；重新预览或重新加载，不能重用旧确认绕过检查。
6. 旧凭证工作配置撤销后，现有网关仍可能接受它。再次按原审批发布流程发布，第二次部署的版本、序列必须更大，且当前双节点确认新Key有效、旧Key无效后才完成该环境轮换。TEST与PROD分别走环境范围和跨环境审批，不能把TEST确认代替PROD结果。

AK在列表仅显示末4位。创建者/撤销者只来自可信审计关联，当前审计页缺少记录或无审计权限时显示未知，不能把Owner当作操作者。

## 部署配置

环境变量使用.NET双下划线映射，例如 `CredentialUsage__FlushIntervalSeconds=15`。Gateway与CP/Worker配置分开管理，修改后通过既有受控维护流程生效。

| 服务 | 配置键 | 默认 | 允许范围 |
|---|---|---:|---|
| Gateway | Enabled | true | true/false |
| Gateway | FlushIntervalSeconds | 15 | 5–60秒 |
| Gateway | CheckpointIntervalMs | 1000 | 100–5000毫秒 |
| Gateway | MaxInMemoryKeys | 10000 | 100–20000 |
| Gateway | MaxPendingBytes | 67108864 | 8388608–134217728字节 |
| Gateway | MaxBatchEntries | 1000 | 1–1000 |
| Gateway | MaxBatchBytes | 262144 | 16384–262144字节 |
| Gateway及CP/Worker | MaxPendingAgeHours | 24 | 1–24小时，双方保持一致 |
| CP/Worker | RetentionDays | 30 | 1–90天 |
| CP/Worker | BatchHashHours | 25 | 2–168小时，至少比MaxPendingAgeHours多1小时 |
| CP | IngestConcurrency | 2 | 1–4 |
| CP | IngestTimeoutSeconds | 10 | 1–10秒 |

无效配置应阻止启动，不能静默降为默认。将Enabled关闭会失去对应节点后续覆盖，不能继续宣称统计完整。新Gateway遇到旧CP的404时有限排队并显示不支持；旧Gateway没有新协议证明，统计不能据在线心跳视为完整。本固定版本已完成新CP／旧Gateway与新Gateway／旧CP的双向短时兼容smoke，保留真实上报404、有界待发及转发200材料；长期容量及完整版本组合矩阵未验收。

## 私有队列与故障处理

队列位于既有LKG卷的 `credential-usage/`，目录0700、文件0600，单写者锁定。`checkpoint.json`含CollectorId、原生产实例、单调序列、未确认批次和缺口；封存核心在重传时保持不变，只有收到对应回执后移除。`clean-stop.json`必须与当前检查点校验和及写实例一致。崩溃、停机、容量、落盘失败和回退均可能使覆盖变为Partial。

进程中断留下的检查点或控制文件临时写入，不会被自动当作可重放的新增量。固定实现按原字节保留到隔离材料，与其他隔离文件共享最多两份预算；超额时在继续写入前拒绝并要求运维处理，保留业务转发。可读的其他节点/控制面身份材料不移动、不采用。没有已提交检查点时，会显式记录中断写入缺口。本固定版本独立owner已完成真实持久卷KILL137与重启去重；这是该次固定版本证据，不代表任意部署或故障都能无损恢复。

遇到Unavailable、重复Hash冲突、游标回退或隔离文件时：保留原检查点及私有失败摘要，核对节点环境、登记秘密、CP地址、只读磁盘/权限/容量和服务端游标，优先修复兼容版本前进。401/403后的上报不会无限重试，恢复身份后通过该节点的受控重启重新绑定。不要删除队列、改写序列、把旧批次换CollectorId重报，或根据一次成功请求把缺报标为已恢复完整。

隔离材料包含敏感节点身份与业务调用关系。公共证据只保留脱敏的数量、Hash和限定标识，不公开APIKey、密码、Cookie、Bearer/JWT、原始检查点或登记Hash。

## 冷备、克隆与兼容回退

原冷备流程已包含DB及全部LKG卷，无需增加第二套原环境备份流程。固定备份工具在停止相关服务后检查各LKG归档的队列，增加私有 `usage-journal-inventory.json`；恢复前重新核对归档、检查点原始字节校验和、Int64序列、Collector与本地身份关系。较旧且没有队列的归档允许标记 `legacy-or-no-journal`；有队列但没有新清单的旧归档仍须检查队列，不能以清单缺失跳过。

完整恢复需要在同一冷备点核对DB回执水位与LKG待发序列，证明未重计。克隆到新owner时先阻断原网络/原CP地址，重绑Collector身份/来源水位，隔离原待发核心；只读清单检查和队列内的逻辑CP地址不能证明网络隔离。

restoreColdBackup先核对不可变镜像内的克隆重绑能力声明，缺失则在创建owner前拒绝。能力匹配时，先设置restore-pending屏障，复制卷后以无网络的离线Gateway命令隔离旧核心，建立新Collector、起始水位1和OwnerClone缺口，再验证回执。全部完成才移除屏障。旧增量可能已入库，不能换新ID重报；不确定未上报部分保留为缺口。重复离线执行仍需相同owner、检查点Hash和节点身份，已产生新调用后拒绝再次重置。本固定版本已在独立owner完成真实冷恢复及新owner克隆重绑，source/clone各自去重后的计数均为1，并验证原CP拒绝克隆collector；不能将复制出的队列接回原平台。

已有待改密账号时，旧二进制不能接管新库来绕过标记。当前实现已将阻断接入原维护工具的迁移和管理进程启动：先只读检查实际数据库，一旦存在生命周期字段，就要求目标不可变镜像的build-identity具有对应构建能力声明，并匹配镜像标签、固定来源和应用Hash。为避免“检查时无待改密账号、随后被其他管理员新建/重置”的竞态，该限制覆盖整个新字段存在期。能力声明不是构建签名，也不能代替安全回归。固定ba9031c已在独立空库owner真实验证：旧226dfe4维护入口被拒绝，CP容器身份、镜像和启动时间未变；兼容版本入口保持可用。后续新快照仍需重验；本固定版本第4包结论以严格验收结果为准。操作上保持新兼容应用运行，优先修复前进；需要回退时单独审阅配对的应用/数据库/秘密/队列冷备方案。数据库Down会丢失新安全语义，不是可直接执行的安全回退步骤。
