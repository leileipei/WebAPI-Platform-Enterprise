# 契约管理补全本机升级操作约定

本页保留契约管理补全当次升级约定：4192/4196/4197、feature/core-loop、本地合并不 push 以及原七份未提交文件均是当时的目标和保全范围，不是当前分支、工作区数量或执行授权。当前代码与安装身份见[项目状态](current-project-status.md)，恢复前置条件见[运行手册](local-runtime-runbook.md)。既有账号、业务、SSO、运行绑定、凭据和历史交付包仍须保留。

先记录原表内容及迁移、受保护文件/凭据摘要、实际部署提交与镜像、环境版本/序列、Keycloak 状态。平台按实际 context 和能力清单计算备份卷，Keycloak 在该实现中为四卷；逐文件回读 SHA，finally 尝试恢复声明服务并核对实际可用性。当前平台恢复还要求 restoreBudget 和真实硬配额 storageVerifier，默认缺失会阻断，不得直接沿用旧演练作为今日恢复证明。恢复演练只使用新 UUID 项目、独立端口、独立空卷及 owner 校验；测试克隆禁止共用原 Keycloak。候选只从不可变 Git archive 构建，显式固定 SDK/依赖锁文件并检查真实镜像 OCI 标记及三个静态文件摘要。

克隆验收包含：旧数据恢复、新增三表的增量迁移、旧软件仍能读取原业务及新增表、候选再次启动；再执行独立 HTTP 契约 fixture、真实 PG/Redis/双网关的导入、示例、比较、风险评审、两角色两级审批、发布/ACK/请求/回滚。测试源只能登记克隆内独立 fixture 的实际地址和限定路径，特殊地址仍拒绝，原4192不得登记测试来源或产生导入/评审/发布 QA 数据。

安装前再次核验 owner、原表/保护文件、冷备恢复证明与实际合并提交。执行软件升级时保留原卷，只增加本批迁移；不从旧冷备覆盖原实例。升级后验证五个应用容器提交/镜像、原管理员只读登录、新页面与静态文件、双网关 Ready/LKG/原环境序列、既有业务请求、四个遥测源及原 Keycloak 登录。原账号密码不改变、不输出到报告。

安装失败时停止候选，使用保留的旧软件镜像重启同一数据卷，保留新增迁移；只有确认没有新 YAML 业务并完成兼容性检查时才可回退旧软件。若已产生旧软件不支持的新业务，使用兼容修复构建，或另建实例恢复备份，不覆盖原数据。恢复服务并记录失败，不能因容器启动成功而宣布升级完成。

最终交付只包含本批报告、规则与实际测试证明、源码清单/补丁及脱敏截图；公开文件禁用符号链接、路径穿越、私有目录和明文凭据，扫描实际 Secret 值，验证 ZIP CRC/SHA。清理仅限已确认 UUID owner 的克隆卷/容器/网络和额外 HTTP fixture；保留冷备及新旧镜像。当次结果分别列出第一批已部署和后两批未实施；后续状态应按对应固定提交与实际证据核对，不能直接复制该阶段结论。
