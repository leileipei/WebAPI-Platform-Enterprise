# 集成测试的 PostgreSQL 分组对照

核对于 2026-11-18，固定基线 `8dd156a7f15ccb01dd54984b5bfff6da7b09d22c`。在同一个本机容器运行环境，固定 149 项集成测试做四组交替对照。分组的全程耗时四组均较短，配对降幅中位数为 **5.64%**。估算删库检查点等待的配对降幅中位数为 **94.12%**。

## 对照条件与结果

三组依次为安全 ACK 68 项、凭证影响 48 项和导入会话 33 项。两种配置都用同一个测试进程、同一个 Redis 和原有并发设置。单实例运行让三组共用 PostgreSQL。分组运行让每组使用不同的 PostgreSQL 和数据卷。锁定镜像、恢复与构建步骤相同。每轮都从新环境启动，计入最终核对和环境清理。PostgreSQL 17.11 的 `fsync`、`synchronous_commit` 和 `full_page_writes` 均开启，其他实测设置一致。分组增加了实例各自的缓存及后台进程，运行环境使用相同的 CPU 和内存容量。

| 1 | 单 → 分 | 138.613 秒 | 128.120 秒 | 7.57% | 53.031 / 3.695 后端秒 |
| 2 | 分 → 单 | 141.551 秒 | 134.247 秒 | 5.16% | 50.324 / 1.806 后端秒 |

| 4 | 分 → 单 | 143.212 秒 | 135.574 秒 | 5.33% | 50.405 / 3.361 后端秒 |

四组通过预先记录的继续条件，即每组总时长缩短、配对降幅中位数至少 5%、且检查点等待下降。八轮均执行相同 149 个用例，零失败、零跳过。每轮核对 150 次测试库及模板的创建和销毁，确认数据库记录和自有容器、卷、网络均无残留。分组的实际独立实例通过集群标识核对。

## CI 调整范围

现有 `contracts-integration` 使用分组配置。三个已测类各自使用独立实例，其他集成测试仍使用原来的数据库服务。导入会话使用的类级迁移模板随所属组，其他类调用共享导入夹具时沿用原配置。集成测试仍由同一个进程无筛选地运行。原 90 分钟上限、断言、并发设置和四项必需检查保持原样。

可用 `WEBAPI_CONTRACT_SPLIT_POSTGRES=1 bash scripts/check-contracts.sh integration` 在本地执行和 CI 相同的数据库配置。独立实例使用相同镜像、私有网络与单独数据卷，原脚本退出时按项目和所有权核对后清理。分组开关只支持集成检查，省略开关仍运行原单实例配置。

这些性能数字来自固定的 149 项样本。CI 同时运行其余集成用例，完整作业时间需以该版本的实际执行记录为准。协议、原始日志、采样、对照统计和清理记录保存在本机 `deliverables/postgres-checkpoint-study-20261118/`。
