## 约束与构建基线

所有外键采用Restrict，保留审计所需实体；以状态停用代替级联删除。复合引用约束保证项目属于组织、Scope环境属于项目、API分组属于项目、Cluster属于环境、Route方法属于同一Route环境。角色分系统 / 组织两种唯一范围。`route_methods`的(environment_id, method, normalized_path)唯一索引承担并发冲突保护，业务保存必须同事务维护。

迁移由EF模型生成，包括关联、唯一索引及有效期 / 超时检查；不在运行时自动建表或隐式种子。独立Migrator从受限Secret文件读取数据库密码，显式执行。`deploy/initial-core.sql`是对应幂等脚本。

治理 2.4 集成候选的历史库升级使用受控 Migrator：它在同一连接和事务中保护现存表、检查迁移历史与结构、调用现有 .NET 通知校验器，再执行迁移。若数据库仍有待执行迁移，且存在 `system.notification` 设置或任何告警通知规则，独立 SQL 会在写入前报告 `managed_notification_validation_required`；这也适用于已包含九字段设置或扩展告警策略的库。应使用同版本 Migrator，不能删除或改写旧配置以绕过检查。没有待执行迁移时可重新检查；空库及没有上述数据的待升级库仍可使用独立 SQL。

受控 Migrator 在成功校验且持有同一事务的写入保护后，对固定哈希 `60f4b634d790ee601fd7c42aec1f56fbe28b0f3307b030cd12374bce9bfdffe6` 对应的 `ExternalNotifications` 历史 SQL 操作只跳过其旧校验块，仍执行其中原有的数据更新。历史迁移源码和迁移 ID 保持不变，但这条受控路径的实际校验语义与原始 SQL 不同；不得据源码未变就声称原 SQL 完整执行。候选实现将校验摘要、可观察的程序集文件哈希和该历史操作哈希写入与迁移同事务的成功回执；该哈希不能证明构建来源或已加载代码的身份。直接调用普通 EF `MigrateAsync` 不具备受控入口的这些保护。

纯 SQL 脚本自行管理完整事务，必须使用没有外层事务的新连接运行。PostgreSQL 17 会话必须显式提供 `webapi.migration_transaction_seconds` 和 `webapi.migration_receipt_max_rows`；缺项或超出范围会在迁移写入前阻断。可通过不含密码的 `PGOPTIONS` 提供这两个设置，再使用 `psql -X -v ON_ERROR_STOP=1 --file deploy/initial-core.sql`。不要将脚本包在调用方事务中；误用会使调用方事务进入失败状态，需要由调用方回滚。成功后脚本输出尝试 ID；直接执行失败的事务内记录会回滚，若没有独立采集证据，结果必须按未知处理。

受控 Migrator 自行管理迁移事务，拒绝加入 ambient／enlisted 事务；未向 EF 登记的外部事务也不能用于这一入口。候选实现持有数据库事务后通过 EF `UseTransactionAsync` 登记，因此事务拦截器会收到 `TransactionUsed`，不会收到原先 EF `TransactionStarting`／`TransactionStarted` 回调。仓库中未发现生产代码依赖这些开始回调，接入方仍需核对外部扩展。

迁移前仍须完成备份、旧控制面及 Worker 停写，并以独立的连接、凭据和角色措施确保旧写入者在迁移期间及迁移后不能重新写入。事务锁随提交或回滚释放，不能证明实际环境的认证入口已隔离，也不能替代对数据库所有者和高权限角色的核验。结构指纹核对还要求外部隔离并发 DDL；没有待升级迁移的重入检查不会锁住业务表。客户端读取预算不严格约束 PostgreSQL 的 TOAST 解压、排序和临时空间。原环境不得用作迁移试验。

### 迁移预算与独立证据（候选）

受控迁移必须显式配置以下变量；范围为输入约束，实际部署的容量应按目标环境评估。不得把隔离测试数值当作生产默认值。

| 变量 | 允许范围 | 含义 |
| --- | --- | --- |
| `WEBAPI_MIGRATION_TRANSACTION_SECONDS` | 60–3600 秒 | 迁移事务总时限；保留原有更短的数据库限制。 |
| `WEBAPI_MIGRATION_SETTINGS_MAX_BYTES` | 1–1048576 | 通知设置单值 UTF-8 字节上限。 |
| `WEBAPI_MIGRATION_RULE_MAX_BYTES` | 1–16384 | 单条通知规则 UTF-8 字节上限。 |
| `WEBAPI_MIGRATION_RULE_MAX_COUNT` | 1–1000000 | 规则数量上限。 |
| `WEBAPI_MIGRATION_TOTAL_MAX_BYTES` | 1–1073741824 | 通知设置与规则累计读取上限。 |
| `WEBAPI_MIGRATION_RECEIPT_MAX_ROWS` | 1–1000000 | 数据库成功回执的最大保留行数；满额时阻断，不能自动删除历史。 |
| `WEBAPI_MIGRATION_EVIDENCE_DIR` | Linux 绝对路径 | 独立持久目录，迁移进程属主，目录模式 `0700`；文件模式 `0600`。 |
| `WEBAPI_MIGRATION_EVIDENCE_RECORD_MAX_BYTES` | 1024–65536 | 独立证据单条大小上限。 |
| `WEBAPI_MIGRATION_EVIDENCE_QUOTA_BYTES` | 至少 4 条记录、最多 1 GiB | 证据目录逻辑配额，不能自动清理。 |
| `WEBAPI_MIGRATION_EVIDENCE_MIN_FREE_BYTES` | 0–1 TiB | 保留的最小可用空间；其他进程仍可能耗尽磁盘。 |

一次隔离测试显式使用事务 900 秒、设置 65536 字节、规则 16384 字节、10 万条、累计 64 MiB、回执 10 万行；证据记录 8192 字节、目录配额 16 MiB、最小剩余空间 1 MiB。这些值不表示生产容量已验收。

受控迁移先持久化开始记录，再在同一数据库事务内检查、迁移并写入成功回执，最后写入独立结果记录。数据库身份无法读取时保留 `Unknown`，不为取证默认授予超级用户权限。数据库提交与独立目录不是同一个原子事务：提交失联、结果文件写入失败、数据库身份或备份连续性无法核验时，结果保持 `Unknown`，不得根据回执缺失推断回滚，也不得自动重跑。`--bootstrap` 和 `--seed-catalog` 在迁移提交后分别记录状态；异常不能说明迁移已回滚。

开始新尝试时，受控入口检查证据目录中是否存在未完成／未知记录，并在实际迁移连接及事务中双向核对提交的尝试 ID 和数据库回执；无法核对、任一侧缺失或历史数据库身份无法核验时返回 `PendingReview`，不执行迁移。创建开始记录时再次比较已核对的日志历史，并对配合此版本的迁移入口使用同一事务级互斥锁。当前回执无法区分受控 SQL 与直接 SQL：若数据库存在没有对应独立证据的 SQL 回执，后续受控迁移会保守阻断，直接 SQL 本身仍可按其既有合同独立运行。此核对不能证明数据库或证据目录没有整体回退；尚无已验收的人工解锁或独立见证服务，不要通过删除记录绕过阻断。

通知预算命中以固定类别记录设置过大、规则过大、规则数量超限或累计字节超限，不保存原始通知内容。只有应用自身事务预算计时器明确触发且外部调用方未同时取消时，才记录事务截止时间命中；数据库或外部取消来源不明确时仍使用相应的通用分类。预算命中不等于回滚已确认。

`--run-sql` 使用同一独立证据目录，但只需要事务时限和回执行数两项 SQL 预算；还须提供容器内绝对路径 `WEBAPI_MIGRATION_SQL_FILE` 和文件字节的预期 SHA-256 `WEBAPI_MIGRATION_SQL_SHA256`。启动前核验最多 16 MiB 的文件并执行同一份已校验字节；哈希只证明字节一致，不能代替签名或可信来源校验。该模式不与 `--bootstrap` 或 `--seed-catalog` 组合。成功退出码为 0，明确失败为 2，结果未知或后续步骤不完整为 3；输出不包含连接信息或原始异常。

运行编排为迁移器使用专用 `migration-evidence` 卷。创建前先持久化所属项目、卷名和随机身份的创建意图；初始化完成后记录就绪状态。中断的创建意图、卷缺失或身份变化都会阻断后续操作，不会自动创建空卷替代；迁移开始至运行状态保存之间另有持久的待核对标记。现有卷仅在身份和权限一致时原样复用。标记与卷并非独立防回退见证。

支持该卷的备份在持有日志锁时归档证据，并在写成功清单前检查归档结构、文件哈希及与真实 Journal 相同的记录语义。恢复首先要求数据库卷、其他必需卷、运行配置及数据库凭据均有清单哈希，并拒绝使用未列入清单的相关密钥或配置；旧备份缺少所需哈希时需要人工核对。清单上限为 4 MiB、4096 个文件，备份文件须由当前用户持有且不向组或其他用户开放，不接受符号链接或硬链接。随后将清单文件逐个复制到私有快照，以固定内存缓冲核验哈希和文件身份，并持久化不含秘密内容的快照索引；恢复读取快照而非原备份，并在完成前复核快照及索引。宿主机空间预检保守计入三倍清单文件总字节、64 MiB 元数据余量、目标预算和预留空闲量，以覆盖快照以及随后复制的密钥和证据归档；这只是时点估算，不能预留物理容量，也不能保证其他进程或实际文件系统元数据消耗不会超出余量。失败的部分副本会保留。

预检通过后，恢复先在目标父目录独占持久化意图记录，保存操作 ID、目标目录和预检记录摘要；之后创建的快照名称携带同一操作 ID。因而即使在快照记录尚未写入时进程中断，仍可通过意图定位候选快照；出现多个候选时必须保留现场并人工核对。新建目标目录时先写入待核对标记，再写 owner 和运行状态，不接管现有目录。目标与快照各保留一份关联记录；这些文件可能在中断时只写成一侧，应结合意图和实际内容核对，不能据单侧记录认定恢复成功。相关记录不是签名或独立见证。

恢复、运行初始化和备份使用按规范目标路径区分的跨进程锁；恢复持有锁直至完成或退出。锁持有者异常终止时留下锁记录，后续操作保护性阻断，不自动删除或重试。待核对标记存在时不能启动或备份；标记缺失也不能单独证明恢复完成，必须能核对操作意图、目标与快照的双向引用和完成记录。候选早期版本若有意图但无完成记录，应保留并人工核对。新目录建立后同步其父目录，父目录不可信、ACL 无法检查或同步失败时阻断并保留已创建材料。当前对 macOS 检查 ACL，对 Linux 依赖可用的 `getfacl`；其他平台及缺少检查工具时保护性阻断。同步失败注入和进程终止测试不能代表实际断电演练，也不能证明所有文件系统、ACL 或跨主机存储的持久化和锁语义。

上述锁仅协调遵守此版本协议的进程；旧工具、直接文件访问或具备宿主控制权的主体不受它约束。迁移及恢复前仍需按前述要求独立停用旧写入者并核验其现有连接。

新意图文件名包含规范目标的摘要，以限制新格式部分写入对其他目标的影响；旧格式的损坏记录若无法确定所属目标，同一父目录仍会保守阻断，需保留记录并人工核对。已有私有运行目录可在目录内部持锁，以兼容应用用户不能写入的父目录；父目录本身的链接会先规范化。恢复在持锁期间报错时保留锁；若必须止损，停止路径可在核对实例 owner 及容器身份后仅停止已确认的运行容器，保留锁、卷和意图。若原恢复进程仍在运行，它仍可能继续操作，不能仅凭这次停止证明其已退出或不会再次启动服务。

完成记录和待核对标记的持久化检查发生在释放锁之前；锁正常删除后不再同步锁目录，以避免删除成功后又因释放步骤报错而失去阻断。断电后可能重新出现已释放的锁，届时保留并人工核对。此设计依赖所用文件系统的独占创建和删除语义；真实断电、网络文件系统及删除操作结果不确定的故障尚未验证。

受控清理在获取锁前后复核目录身份和 owner，删除目标目录前再次核对；父目录不可写时只允许保留证据和目标目录的分支，涉及删除目录的分支会在停服务前阻断。隔离测试以同用户不可写目录模拟权限边界，尚未验证真实 root 所有的父目录。

清理还须检查父目录及祖先的写入权限和 ACL；其他用户可以替换目标目录项时会阻断。若父目录不可列举，系统无法确认是否存在不能按目标归属的旧意图，当前运行、备份及清理入口会保守阻断；例如 root 所有的 `0711` 父目录是尚待处理的兼容场景。

运行、流水线和跨环境验收将失败状态与异常内容分别记录；即使回调以空值拒绝或错误消息为空，也保留失败现场。原始错误与后续清理、证明写入错误同时存在时，会保留主错误并附带后续错误；这些本地记录仍不能替代独立审计或防回退见证。

流水线和跨环境验收将各后续失败按阶段及消息摘要登记；原环境保护检查未完成时状态为 `Unknown`。若证明文件本身无法写入，对应错误只能附在返回异常中，不能声称已经持久化。若原异常已有同名只读字段，系统以包含原异常的包装错误承载新证据，不覆盖原字段。

新生成的流水线／跨环境证明先持久化待完成标记，再写入不宣称验收通过的 `proof.json` 和绑定其字节摘要的回执；完成后才移除待完成标记。写入前按读取器相同的 16 MiB 上限检查序列化字节。官方目录验证入口检查标记与回执；直接查看原始 `proof.json` 会看到待核验状态，因此归档时应保留整个证明目录。旧版无此标记及回执的证明维持原有读取合同，可能包含链接或大文件，因而只应从可信来源读取；它不因此获得新的持久化证明。若写入或同步失败，标记和部分文件保留，验收状态为 `Unknown`；标记删除结果不确定、真实断电及网络文件系统仍未验证。

运行、流水线和跨环境三个验收入口在报告持久化前保留其自有源与恢复夹具。流水线在关闭前后分别观察原环境，任一观察到变化为 `Changed`、无法观察为 `Unknown`。流水线和跨环境业务执行成功只记录 `executionPassed`，保留夹具期间 `isolatedAcceptance` 仍为 `false`；运行验收记录各分项，`complete` 仍为 `false`。须另行核验现场、身份和清理结果后才可完成验收。当前尚未提供该复核及清理结果的自动闭环，保留的服务和卷可能继续占用资源，不能将现有流程称为全部通过。其他未列出的验收脚本不因此自动具有相同保证。

候选命令 `node scripts/delivery/reviewed-cleanup.mjs plan <证明目录绝对路径> <Unix socket 绝对路径>` 仅只读汇总证明和资源元数据，明确显示迁移待核对标记及 `Blocked` 状态；计划摘要只用于比对本地内容，不构成执行授权或证明真实业务验收。命令显式指定并复核 Unix socket 文件身份，屏蔽继承的 Docker context／host／TLS 设置；路径仅接受 ASCII 字母、数字、斜杠、点、下划线和连字符，socket 父目录必须由当前用户拥有且为私有目录，因此常见共享 socket 目录和含特殊字符的路径会被保守拒绝。这只限定本地 socket 传输，不能证明其后端或存储位于本机。当前 `execute` 入口始终保护性阻断，不会停止或删除资源。恢复复核可检查意图、输入快照／目标的双向引用与完成记录是否匹配，但逐文件读取不是跨文件原子快照，也不能证明备份来自所称源环境，或证明数据卷内容、真实硬配额和防回退连续性。旧的其他清理函数仍存在，不能据此认为所有历史清理路径均已关闭。

流水线故障诊断限制对象深度、字段数、字符串和总数据量，循环和截断会标记，并对常见敏感字段名遮蔽；这不是完整的秘密检测。诊断目录仍须按私有敏感材料保护。普通对象形式的拒绝消息会有界保留，原始拒绝原因留在进程内的异常 cause 中，不代表已经持久化。

克隆验收分别记录恢复结果、后续场景结果和现场观察；待核对为 `PendingReview`，失联或未返回的结果为 `Unknown`，不能从场景异常推断恢复已回滚。记录已分配项目及目标路径，区分缺失、目录、符号链接、其他文件和无法观察；目录存在不代表 owner、意图或完整性已经核验。保存恢复返回的快照路径或异常中可获得的快照路径，并分别记录可观察状态；父目录仅是后续查找意图记录的位置。运行验收将多个收尾失败按阶段记录；文件写入／同步及关闭同时失败时保留两种错误，未成功写入的错误仍不能声称已持久化。

恢复会交叉核对清单、release 和可用的 runtime 版本，并从该固定版本读取已登记的部署合同，确定必须保留的密钥和功能资源；版本或合同无法读取时阻断。当前登记覆盖仓库四种历史初始化脚本和候选脚本，单独识别脚本合同不等于完整旧库恢复已验收。通知、缓存、交付和流水线出现关联资源时，必须同时满足各自的配置、回执和卷清单要求；流水线还须预先核对交付配置、原拥有者和生产目标。恢复要求显式提供快照字节上限、目标卷字节上限、宿主机最小空闲量和目标存储最小空闲量，并由可信实现核验实际硬配额和目标身份。候选流程计划在复制前核验范围，创建带独立身份的空卷后、首次初始化写入前核验全部写入卷，再在解包前复核，并保留各阶段检查记录；范围包括业务、密钥、引导、通知及证据卷。**当前候选仅定义了验证接口，尚未接入可证明实际硬配额的实现；默认调用会在创建快照和恢复卷前阻断。** 接口输出的普通 JSON 和哈希本身不能证明配额真实存在。隔离测试注入的合成结果只用于验证控制流程，不能用于实际恢复或证明存储隔离。即使以后接入真实配额，宿主其他进程和临时容器写入的容量仍须由目标环境的容量管理解决。

配额检查记录包含四项预算、运行关联 ID、前一阶段记录摘要及 JavaScript provider 源文本指纹；该指纹不包含闭包状态，也不是签名或可信版本证明。记录格式 2 的前一阶段摘要按落盘文件的完整 UTF-8 字节计算，包含末尾换行；早期无格式标记的测试记录保留原样，不能按格式 2 直接验链。阶段推进基于进程内记录，未在每个阶段重新读取前一份磁盘文件；离线审计须重新计算实际文件摘要。归档中有未决尝试时，恢复在创建卷和解包之前保持待核对。初始化前，候选编排对 Compose 的实际合并配置核对各服务的卷来源和目标、只读输入、命令、项目及 owner，要求只读容器层、无网络和有界临时盘；通知归档比较另使用 64 MiB 临时盘及 256 MiB 容器内存限制。隔离容器中正常通知比较通过，65 MiB 合成文件在临时盘写满后被拒绝；这不能证明目标卷已有硬配额，也未覆盖所有产品 overlay。恢复解包的宿主输出采集上限为 1 MiB，超限时继续排空输出并在进程退出后报告截断失败；该机制本身不提供恢复进程的总运行时限。候选恢复路径通过无网络标准输入流校验迁移证据归档，并在目标数据库启动后以只读事务比较实际证据目录、归档摘要和数据库回执及可观察身份；校验无法完成时保留待核对标记和现场。旧镜像若不支持恢复核验命令也会阻断，不能以空目录或删除标记绕过。标准输入方式已在本机隔离容器中验证，原生 Linux 的 rootless／user namespace 环境尚未验证。快照和本地哈希不能防御有权修改同一用户文件或控制容器宿主机的主体。

在更严格的初始化挂载合同下，一次独立 PostgreSQL 物理冷备演练通过了恢复入口、合成卷初始化、归档解包及数据库回执核对；它使用合成 Compose context、合成初始化脚本及未提交候选镜像。另一次隔离演练使用合成密钥验证了产品的基础、通知、交付和中间阶段初始化服务以及 26 个新卷的映射。两项演练均使用模拟配额，未覆盖完整网关、真实缓存与应用启动，也不是生产恢复验收。独立 cleanup 函数按身份检查处理证据卷；上述三个验收入口现阶段在写入报告之前保留全部自有源和恢复夹具。新的场景证明写入独立运行目录且不覆盖旧 proof。新版本证明须关联克隆独立项目、owner、目录和保留结果；旧版本证明保留原有判定，但明确不表示已验证新增的克隆保留事实。相同的数据库及证据卷仍可能一起回退，因此即使恢复核对成功，独立历史连续性仍为 `Unknown`；普通文件哈希和本地持久标记不能替代独立见证。
