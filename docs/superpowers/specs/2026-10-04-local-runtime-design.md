# 独立本机完整运行环境设计

日期：2026-10-04。状态：用户已确认设计；实施计划待审阅，尚未实施。

## 1. 目标与当前事实

用户已选择「A：独立本机完整运行环境——长期运行双网关、三源与告警，保留现有数据」。本阶段把已交付的真实核心、控制台、观测与站内告警组合为可以持续使用、停止后恢复的本机环境。沿用既有页面、字段、权限、发布审批和告警生命周期。

当前代码基线为 `df5f4d1`。只读核对显示：现有 `webapi-enterprise-core-test` 项目运行 PostgreSQL、Redis 和 5090 控制面；它属于校验栈。现有观测 Compose 中 Loki、Tempo 使用 tmpfs，验收脚本还共享源码目录中的 bin/obj，均不适合作为长期运行环境。本机 Docker 为 Linux ARM64，分配内存约 16 GiB。

**数据保留的明确解释**：原项目、原数据库、原密钥、原交付包和 4180/4181/5090 入口保留；新环境使用独立新库，不自动复制旧库。新环境创建的配置、业务对象、审计和告警随后持久保存。旧数据迁移不属于本阶段。若用户要求旧数据直接出现在新界面，应先调整此设计，再实施迁移。

成功标准是独立环境实际完成双网关发布、真实 HTTP 请求、指标/日志/Trace 查询、站内告警处理，并在停止、重启后恢复配置和持久数据。容器启动成功、页面可打开或收到 OTLP 200 均不足以单独证明链路完成。

## 2. 路径比较与选择

| 路径 | 优点 | 代价与适用性 |
| --- | --- | --- |
| 独立持久 Compose 项目，推荐 | 旧环境保持完整；入口稳定；数据与交付版本独立；可以精确启停 | 需要新增运行编排、初始化和运维脚本 |
| 将现有校验栈直接改为常驻 | 初期配置少 | 会把验证、共享构建目录和原数据耦合；不符合独立运行目标 |
| 应用在本机进程中运行，只容器化数据源 | 本机调试方便 | 启停和版本管理分散；宿主依赖更多，恢复流程较复杂 |

采用第一条路径。既有 Compose 与验收脚本继续承担原用途，不改名、不接管、不共享其卷。

## 3. 服务拓扑与入口

固定 Compose 项目名为 `webapi-enterprise-local`。管理服务为 ConsoleHost、Control Plane、Worker；数据服务为 PostgreSQL、Redis；代理服务为 Gateway A、Gateway B；观测服务为 Collector、Prometheus、Loki、Tempo。

| 入口/服务 | 默认地址或连接方式 | 职责 |
| --- | --- | --- |
| 控制台 | `http://127.0.0.1:4190` | 提供已构建静态页面，同源转发 `/api` 到控制面 |
| Gateway A | `http://127.0.0.1:4196` | 真实 API 代理，独立身份和 LKG |
| Gateway B | `http://127.0.0.1:4197` | 真实 API 代理，独立身份和 LKG |
| Control Plane、Worker | Compose 内网 | 权限、配置、发布协调、查询与告警评估 |
| PostgreSQL、Redis、三源、Collector | Compose 内网 | 数据存储、消息/缓存与遥测处理 |

默认端口是设计值，尚未证明空闲。允许配置本阶段端口；启动前检查冲突并明确报错，不终止占用者、不自动接管旧入口。内部服务不映射宿主端口。诊断通过本项目内网或只读管理命令进行。

浏览器 → ConsoleHost → Control Plane → PostgreSQL/观测源；Gateway → 企业明确配置的上游；Gateway → Collector → Prometheus/Loki/Tempo；Worker → PostgreSQL/Redis/Prometheus。浏览器不取得数据源凭据或任意源查询 URL。

## 4. 发布产物与隔离

新增 `deploy/compose.runtime.yml`，管理服务与网关配置分开呈现，未绑定环境时不要求填写虚假的 EnvironmentId。应用从明确的不可变提交构建，使用独立构建目录或构建阶段，不挂载工作目录、bin/obj 或开发依赖缓存到运行容器。ConsoleHost 使用同一提交生成的控制台静态产物。

沿用 `deploy/images.lock.json` 已固定的第三方镜像摘要。应用镜像以已锁定的 SDK 镜像承载发布文件，以避免本阶段增加未核实基础镜像；运行应用使用 UID/GID 10001。文件系统尽可能只读，写入限制在声明的卷或临时目录，关闭额外 capability。首次卷初始化如需权限调整，只允许精确的本项目卷与声明的服务 UID；初始化 helper 完成后退出，不取得宿主源码或 Docker socket。

版本清单记录源提交、构建时间、应用镜像 ID、依赖镜像摘要、静态产物哈希和配置格式版本。运行中的版本不随工作区文件变化。构建失败保留当前版本；前置检查失败不先停止现有服务。升级迁移失败停止该次升级并报告，不能把镜像切回当作数据库自动回滚。

## 5. 两阶段初始化与操作契约

统一命令入口拟为 `scripts/local-runtime.sh`，具体参数与错误码在实施计划中展开。所有命令绑定固定项目名及其本阶段运行目录，不从宽泛名称推断清理对象。

| 操作 | 行为 |
| --- | --- |
| `init` | 检查 Docker/版本/目录；生成本阶段秘密；要求显式管理员用户名；提供或生成 0600 引导密码文件；建立空库并执行既有迁移与显式 bootstrap；重复调用不重置已有用户密码 |
| `up`，未绑定环境 | 启动管理端、Worker 和三源；状态明确显示网关未配置；用户可登录建立业务环境 |
| `configure` | 输入真实 Active 环境 ID 和上游 origin 白名单；验证环境与节点绑定；生成两个不同秘密的注册配置；重建控制面加载注册配置，启动双网关 |
| `up`，已绑定环境 | 读取已保存配置，启动完整栈，检查管理端、双节点及三源就绪 |
| `status` | 显示版本、服务状态、入口、节点 ACK 与数据源可用性；分别报告未配置、未就绪、源异常，不统一包装为健康 |
| `stop` / `start` / `restart` | 精确操作本项目；保留数据库、源数据、LKG、密钥与配置 |
| `complete-bootstrap` | 用户确认已保存凭据后，删除本阶段一次性引导密码文件；长期服务不挂载该文件 |

`configure` 在配置落盘前校验格式、环境存在且 Active、节点名称绑定及白名单。首次节点名为 `local-gateway-a`、`local-gateway-b`。重复配置相同环境应幂等。已有绑定改成其他环境直接拒绝，避免把旧 LKG/节点秘密带到另一环境；迁移绑定需后续独立流程。

控制面支持空注册集合，当前代码对此没有抛错；Gateway 需要真实非空环境 ID。因此先启动管理端再绑定网关是必要步骤，不使用 Guid.Empty 或预建假业务环境。配置时的认证沿用控制台会话与 CSRF，密码/会话不写入常驻配置或命令行日志。

容器采用 `restart: unless-stopped`；Docker 引擎重新可用时遵守容器重启策略。手动停止后须显式 start/up。此设计不安装 LaunchAgent，也不承诺 Docker 未启动时服务可用。

## 6. 持久存储、会话与秘密

| 数据 | 保存位置与恢复语义 |
| --- | --- |
| 配置、权限、审计、发布、规则和事件 | 独立 PostgreSQL 持久卷，沿用 EF 迁移 |
| 双网关最后可用配置 | 两个独立 LKG 持久卷，不互相覆盖 |
| ASP.NET Data Protection keys | 独立持久卷与固定 ApplicationName，控制面重建后可解密原会话 |
| Prometheus | 持久卷，保留期 7d、容量配置 2GB，先达到的限制可能缩短历史 |
| Loki、Tempo | 普通持久卷，替代校验栈 tmpfs；配置保留期 168h |
| Redis | 作为可重建通信/缓存使用；重启后通过既有数据库、快照、节点重注册路径恢复，不作为配置账本 |
| 环境绑定、入口、版本清单 | 本阶段独立运行目录，不含明文密码，不打包用户配置 |

新增可选 Data Protection 目录与应用名配置，保持原校验栈默认行为。当前本机入口为 HTTP，使用现有 Development cookie 策略，保留 HttpOnly、SameSite Strict、CSRF 与 Origin 检查。此配置不得宣称满足公网生产安全部署；原生产 Secure cookie 规则保持。

首次生成独立 PostgreSQL 密码、两节点秘密、IP HMAC 密钥与游标签名密钥。禁止复用原项目秘密。秘密文件 0600，目录仅当前用户可访问；挂载只读，容器内读取权限须验证。秘密、Data Protection keys、用户数据库与运行目录均排除源码包和日志。服务就绪后保留供再次启动必要的秘密，禁止套用临时验收退出即删除所有秘密的逻辑。

正常操作不调用 `down -v`、不删除卷、不执行全局 prune。此阶段不提供自动销毁数据命令。卷保留不等于备份；提供中文备份/恢复操作说明和本阶段精确对象清单，备份由操作者显式执行，恢复演练使用独立验收项目。

## 7. 运行参数与业务边界

三源地址、Collector 地址固定为本项目内网服务地址，继续使用既有脱敏、信号覆盖、超时和安全查询规则。告警默认槽 15 秒、查询延后 30 秒、租约 30 秒、并发 4；网关默认指标导出 15 秒、Trace 采样 0.1。真实验收可在独立验收项目显式调整采样和时间参数，但不把其短窗口写为长期默认。

Collector 沿用内存队列，不声称重启时零遥测丢失；缺口继续标记 Partial/Unknown，不补造历史、不自动把故障事件判恢复。源故障不阻断网关代理。站内事件保存在 PostgreSQL，外部 Email/Webhook/IM 仍未实现。

Collector/Prometheus/Loki/Tempo 沿用 256/512/512/768 MiB 的初始内存限制；应用、数据库及 Redis 另给明确限制并记录实测使用。普通 Docker 卷不承诺每项目硬磁盘配额。status/运行手册提供磁盘使用查看方式；主机空间不足应明确诊断，不自动删除用户数据。7 天实际保留与容量上限必须通过相应时长和负载验证，短期重启测试不能代替。

默认不创建示例 API、审核账号、业务权限或告警规则。可选 `demo` profile 仅提供标明「示例 HTTP 后端」的内网服务，禁止对外暴露其控制接口；业务资源仍由用户按正常页面和审批流程创建。企业上游需要用户显式提供地址和凭据，凭据沿用既有业务管理方式。API 上游 origin 必须配置白名单。

生产发布的双独立审核、最少两个节点、ACK、LKG、并发版本校验及权限边界保持原行为；本机运行不绕过审批来制造成功。

## 8. 故障与恢复

启动等待设置明确超时并逐服务报告；健康检查不就绪则不宣称完整运行。PG 不可用保留卷与版本信息；Redis 重启后验证真实发布/节点协调恢复；控制面暂时不可用由网关既有 LKG 路径承接。网关重启使用新 InstanceId 重新注册，发布成功仍需要当前实例 ACK。

Worker 重启后遵循 PG 租约接管，不直接改表清除锁。已确认、静默或抑制的告警状态按既有生命周期继续。Collector/源恢复后验证新样本推进，同时保留历史缺口。任何初始化或配置失败均保留当前状态、给出可重试步骤，不隐式重置数据库、密码或环境绑定。

## 9. 验收与交付

先验证运行编排、卷权限、配置校验、初始化幂等及秘密排除；新增测试集中覆盖 Data Protection 持久配置和运行生命周期风险，不重写全部已通过的旧测试。

建立独立随机验收项目，使用相同不可变应用镜像、运行编排与持久卷类型，所有创建对象带该次项目标识。完成以下证据：

1. 首次初始化登录，保存真实业务环境；绑定两个节点并通过既有发布审批，确认两当前实例 ACK。
2. 两网关真实 HTTP 请求到示例后端；查询真实指标、日志与已采样 Trace。规则真实触发、恢复和人工处理，保留审计。
3. 保存环境、发布版本、规则/事件、日志 ID、Trace ID；停止全部服务再启动，核对 PG 对象、两份 LKG、源历史与新采集数据。指标历史按源保留配置验证，不要求 Redis 保留临时缓存。
4. 重建控制面，原有效会话保持可解密，CSRF/Origin 规则仍有效；网关重建后新 InstanceId 与当前版本重新 ACK。
5. Redis 重启后真实配置协调恢复；源停机时界面报告源异常/覆盖缺口；Worker 恢复后正确接管且无重复事件转换。
6. 精确清理仅该随机验收项目与其合成秘密；核对容器、卷及文件无残留。正常长期项目 stop/start 全程保留数据。

长期项目验收只做启动、状态、登录入口及用户授权的业务配置；不自动植入验收账号和规则。交付前后记录原项目容器 ID、镜像、卷挂载与入口状态，确认未对原栈执行 mutation；原库原卷未替换，不能只凭旧入口 HTTP 200 声称所有旧业务数据已逐行验证。

交付包括：运行 Compose、不可变镜像构建与生命周期脚本、中文本机运行/备份恢复手册、版本清单、实际验收证据，以及独立的新交付包。沿用旧 40 页原型和源码交付包；新包不覆盖它们，也不包含账号、数据库或秘密。

范围不包括旧库迁移、策略中心、Breaking Change、SSO、新业务页面、生产 TLS/HA、企业上游接入、外部通知及生产容量/SLA 验收。完成后分别陈述本机实测结果与未验证项目。

## 10. 设计自检

本规格将范围选择与设计审批区分；新环境与原库关系明确；空环境初始化与网关绑定有确定顺序；运行构建不依赖共享 bin/obj；普通启停不删除数据；遥测重启缺口、Redis 重建及会话密钥均有恢复语义；本机 HTTP 与生产验收边界明确。默认端口需启动前核验，资源限制需实施期验证，均不是已发生的运行结果。
