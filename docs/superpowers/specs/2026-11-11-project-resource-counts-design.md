# 项目列表资源计数设计

用户已确认 A 口径。项目管理列表增加环境数、API 数和项目应用数，分别对应 P04-C03、P04-C04、P04-C05。

环境数统计当前账号具有 environment.read 权限的环境，包含治理列表可见的停用环境。API 数统计具有项目级 api.read 权限的项目 API，每个 API 计一次，包含各生命周期状态。项目应用数统计具有项目级 app.read 权限且 ProjectId 等于该项目的应用，包含停用应用。组织共享应用的 ProjectId 为空，项目应用数排除这些应用。有读取权限且集合为空时显示 0，无相应读取范围时返回 null，界面显示 —。只有环境范围权限时，环境数反映可见环境，API 数和应用数返回 null。停用组织或项目的业务资源遵循现有读取权限规则。

沿用项目可见性判断，先筛选并分页，再对该页项目批量查询计数。列表行新增可空 environmentCount、apiCount、applicationCount 字段，其余列表字段与分页结构沿用现有接口。使用专用 ProjectListItemDto，详情、保存和 scope-tree 继续使用 ProjectDto。

复用 CollectionAuthorizationQuery 的功能权限、组织角色和数据范围匹配。每类计数执行一次批量查询，重叠范围采用现有 EXISTS 判断避免重复。首版即时查询，无需新增存储字段。

验收覆盖空项目、多个环境/API 版本、项目及组织共享应用、重叠授权、仅有环境范围、功能权限撤销、停用资源与祖先、跨项目和跨组织隔离、分页边界、现有详情和 scope-tree 的响应兼容性。
