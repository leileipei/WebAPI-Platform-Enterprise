# 凭证创建幂等与秘密回执

本次按用户确认的旧治理迁移审查第01项实施，基线为 main `a2cdc031430f30e23a75d5b5548fa50d599736ff`。仅迁移凭证创建幂等与秘密回执；旧资料原样保留。

创建请求必须提供有效 `Idempotency-Key`。服务端在现有受审计事务和授权写锁内重新确认当前操作者、应用实际范围、管理权限及应用状态，再核对绑定操作者、实际范围、操作名、应用ID与UTC有效期的回执。同键同请求只创建一次；同键异请求返回409；缺失或非法键返回422。

首次成功响应含完整秘密；回执只持久化凭证元数据。同键重试返回同一凭证元数据、空的 Secret/ApiKey 和 `SecretUnavailable=true`，不会重新生成或恢复秘密。首次响应丢失后也保持此规则。回放是原创建结果的元数据，不代表凭证当前仍有效；读取当前凭证使用现有GET。

不改变普通凭证范围、撤销、风险确认、发布与轮换语义。沿用主线现有 IdempotencyRecord 表、唯一约束和事务写锁，不新增数据库迁移。回执与凭证/修订/审计必须在同一事务提交，失败不留下部分创建结果。

选择独立的 CredentialCreateReceiptService：将仅持久化元数据的边界保持在创建服务内。直接包装完整响应会持久化秘密；整包移入旧治理服务会携入环境绑定与安全通道，均不采用。

控制台沿用编辑器现有请求键。同键回放后明确提示“凭证已创建，秘密无法再次获取”，不展示空秘密，也不自动创建替代凭证。首次响应保留原一次展示流程；普通轮换创建回调仍接收同一凭证ID。

验证覆盖真实HTTP与PostgreSQL的并发/重放/重启、请求冲突、UTC规范化、操作者与应用隔离、当前角色/范围/账号/应用状态变化、事务回滚，以及回执、审计、GET、列表均不泄漏秘密或哈希。前端验证首次展示与回放提示，并保留全部主线必需检查。
