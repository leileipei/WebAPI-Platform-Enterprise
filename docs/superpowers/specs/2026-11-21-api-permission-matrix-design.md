# API 授权矩阵设计

基线为合并 PR #23 的 main `3b8a672a99d84e17ea9ff887b35267bdaf326eba`。本批覆盖原第 21 页的 11 个需求。消费应用管理员需要核对每个 API 在各环境的工作授权，能一次提交多个单元，并看清这次变更和已确认发布的区别。

## 矩阵和读取范围

API 为行，环境为列。项目应用固定所属项目。组织共享应用可选择同组织下可读项目。服务端先检验应用 `app.read` 与项目 `api.read`，环境列取启用环境的 `environment.read` 与 `app.read` 交集。列表稳定分页，支持跨页选择。切换项目和权限范围时清除旧选择。工作授权显示模式、有效期以及按服务端时间计算的待生效、窗口内和已过期。

操作继续要求应用和目标环境的 `app.permission.manage` 与可写 Scope，路由方法选择还要求 `route.read`。已选空单元可授权，已有授权的单元可修改有效期或撤权，单条授权可编辑路由方法或由旧版转为路由方法。选中一条旧版授权及同项目的空单元可原子移动，保留许可 ID，预览同时展示移出和移入。原单条 HTTP 移动请求继续兼容其现有范围。按现行严格环境规则校验旧版授权。新路由授权须显式选择路由、HTTP 方法和授权修订。

应用详情及原授权列表使用相同读取边界。没有 `route.read` 时隐去方法详情。应用详情中的运行版本受 `gateway.config.read` 约束。响应形状和凭证读写契约沿用现有定义。

## 预览与提交

本批采用专用批量命令，复用现有单条授权校验和环境审计。逐条由前端调用旧接口会在一项失败时留下部分授权，不能提供批次事务。暂不引入新的持久化模型。提交批次限制为 20 个单元。

预览显示每单元的工作配置前后差异，包括模式、窗口和可读方法。使用既有 `RunningDeploymentReader` 读取有 `gateway.config.read` 权限的环境。仅在发布、不可变快照和当前节点确认均齐全时展示已确认基线，缺证处保留未知。预览按照工作或快照路由自身的授权修订标识失配方法。DTO 只包含授权数据和确认依据，不包含凭证或快照字节。工作配置须走现有发布流程才会影响网关。

预览凭证绑定操作者、应用、项目、规范化请求及相关状态，五分钟有效。提交在授权治理锁和环境锁内复验会话、Scope、修订及预览。目标包含生产环境时，矩阵命令要求明确勾选确认。已部署的单条接口使用原请求契约，生产确认是矩阵命令的约束。批内逐项审计与幂等回执共用一个事务，任一失败整批回滚。重放先复验当前权限。

撤销路由方法授权需在同一事务删除方法子记录和父授权，并更新应用和环境授权修订。控制台遇到过期预览会要求重新查看。授权修订冲突后重新读取。结果不明确时保留原提交和幂等键供核对。界面保留取消、键盘操作、权限收窄后的清理和明确错误。

## 验收边界

真实 PostgreSQL HTTP 回归验证事务、授权、跨环境限制、旧接口兼容和并发变化。浏览器从固定产品提交构建并使用隔离合成夹具，按 P21 原 ID 记录页面、只读、新增、有效期、生产确认、撤权及结果读回。真实企业发布、现场节点和候选范围沿原台账处理。
