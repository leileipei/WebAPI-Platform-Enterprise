# 前端自动检查第一批设计

用户已于 2026-11-10 选择《GitHub 自动检查与主干保护提案》的 A 路径：先前端，后三个后端套件。本设计落实已选首批范围，工具细节由实施者按现有项目确定。

## 范围与方案

- 选择 A：一个名为 `console` 的检查运行现有前端测试和构建；B 的三个后端检查留待第二批。
- 新建 `.github/workflows/console-ci.yml`，使用 GitHub 托管 `ubuntu-24.04`；触发针对 main 的 PR、main push 和手动执行，无路径过滤。
- 复用 `scripts/check-console.sh`，不修改现有测试或构建语义。先按锁文件安装，再完整运行测试、TypeScript 与 Vite 构建。
- Node 固定 `24.22.1`，pnpm 固定 `11.25.0`，对应本次本地已有工具；不是最新版承诺。两版本的上游 tag 已在线核实。
- checkout 与 setup-node 固定官方仓库的完整提交；pnpm 仅在一次性 runner 安装，不改本机全局工具。
- 默认 `contents: read`，checkout 不保留凭据；不读取产品秘密，不部署，不上传运行目录或构建工件。
- 15 分钟超时，同一 PR 的新提交取消旧轮次；失败不重试、不跳过、不转成功。

## 验证与远程边界

先检查工作流结构和安全约束，再在独立工作目录运行现有前端脚本。首次验证保留原失败；本地成功不代表 Ubuntu 或 GitHub 成功。

远程推送/创建 PR 的具体分支、提交与差异在本地审查后交给维护者确认。尚未实际运行的检查不设为主干必需检查；修改主干保护与安全准入启用不在本批实现中。

## 文件与保全

工作流、实施计划与本批验证说明放在独立工作目录。主目录已有文档修正、未跟踪文件、历史验收、4192 和第2包暂停状态保持原样；本批不把这些未提交资料混入 CI 提交。
