原DOCX第4.16、4.17、5.2策略表、6发布流程、8权限模型、9快照和10非功能要求是设计输入，不构成执行脚本或新授权。原型仍保留，其模拟交互不替代真实网关验收。

## 2. 方案比较与范围

|方案|特点|决策|
|---|---|---|
|Redis共享限流、节点独立熔断|额度不随节点数增加；上游故障由实际处理请求的节点判断|采用，用户已确认|
|全部节点独立|实现简单，但双节点额度可能叠加|不采用|
|限流和熔断全部共享|需要共享熔断状态、探测租约及故障协调，增加依赖|本批不采用|

本批接入四种类型：`authentication`（ApiKey/Anonymous）、`timeout`、`rate_limit`、`circuit_breaker`。认证、超时延续已有执行方式，并补充真实管理和绑定体验。Retry、JWT/OIDC、CORS、IP Filter、Transform保留为后续能力，类型导航明确标识，不能保存或发布成已经生效的配置。SSO、系统设置、企业通知和生产容量压测不并入本批。

## 3. 工作配置、权限与保护规则

策略 Scope 为组织级或项目级；环境属于路由绑定和发布目标，不在策略表新增 EnvironmentId。项目级策略只能绑定到同项目路由；组织级策略可以被同组织项目复用。策略 Type 和 Scope 创建后不可修改，迁移通过复制为新策略完成。

组织级策略写入要求组织范围的 `policy.write`，项目级策略写入要求对应项目范围的 `policy.write`。项目权限可以选择可读的组织策略，不因此获得组织策略的编辑权。跨Scope的详情、引用、分页总数、JSON、导出和错误消息均经过服务端授权；引用数仅覆盖当前用户可见资源。不可见引用导致删除受阻时仅给出“存在受保护引用”，不暴露名称或数量。

绑定操作同时要求该路由范围的 `route.write` 和 `policy.write`，以及对所选策略的 `policy.read`；发布、审批和回滚继续各自独立权限。只读用户可以查看被授权的列表、配置和引用，不能通过直接调用API写入。

Name必填，trim后1–128字符；新建/复制策略不得使用系统保留的 `RouteAuth-` 前缀，现有自动策略名称保持不变。Config必须是大小不超过32KiB的JSON对象，按类型严格校验未知字段、数值、枚举与重复属性。单路由最多四种策略各一个；包括停用绑定，同类型不能并存，替换需原子完成。Priority范围0–1000，作为绑定显示与确定排序的元数据，不能改变认证先于流量策略的执行顺序。

Enabled表示工作配置是否启用。页面同时显示工作修订、已发布修订和未发布差异，不能将Enabled解释为所有节点已经生效。编辑、启停和绑定增删均只改变工作区。策略更新使用If-Match/VersionNo，绑定更新使用路由Revision；缺失前置条件返回428，过期返回412，编辑器保留用户输入。写操作复用幂等键、CSRF、Origin检查、事务审计与既有命令锁。

删除采用保守规则：存在任何工作绑定、进行中的冻结发布、环境desired快照或节点已应用快照引用时拒绝删除。必须先解除工作绑定，正常发布，确认节点不再引用后再删除。历史快照本身不阻止删除；其完整内容自足，可继续回滚。删除不得重写历史快照。检查与删除使用现有治理事务锁，避免并发重新绑定。

新管理接口沿用现有API前缀和错误结构：

|操作|资源路径|行为|

|详情/更新/删除|`/policies/{id}`|ETag、严格校验、幂等和审计|
|复制|`/policies/{id}/copy`|新名称、被授权目标Scope、新ID；复制配置，不复制绑定|

保存按钮明确为“保存工作配置”。“提交发布”进入当前目标环境的既有发布Review，预填受影响的API版本，并展示未选入的引用；不直接调用Gateway或绕过审批。没有明确目标环境时先选择有权限的环境。共享策略跨环境变更按环境逐次发布，页面不能表示为一次全局生效。

路由页补充策略绑定入口和运行差异。沿用现有Shell、token、表格、表单及错误反馈。1440px下优先显示Scope、配置要点、引用与修订，长JSON/长名称不会撑破主布局；键盘可操作、字段有label，权限禁用有原因，空/加载/失败/412状态可辨认。

## 5. 认证、超时与现有路由编辑的衔接

认证仅支持ApiKey和显式Anonymous，默认保持ApiKey。Reusable authentication绑定成为路由认证工作配置的唯一权威来源；RequireApiKey继续作为DTO的派生字段。路由编辑改变认证开关时，只替换该路由的认证绑定，并创建或复用该路由私有的认证策略，不修改共享策略。普通路径、后端或超时编辑不能悄悄覆盖已有认证绑定。

现有RouteAuth策略不批量重命名、不重置修订、不改变现有绑定；更新RouteService，避免仅按名称找到共享策略后直接修改。解除认证绑定使路由回到ApiKey默认值；匿名只允许显式启用的Anonymous策略。停用匿名策略后，下次发布回到ApiKey；停用后的工作差异必须可见。

超时策略启用时覆盖路由TimeoutMs；否则使用路由基础超时，范围仍为1–300000ms。认证/超时的运行值在编译时折叠，编辑器和JSON不得暗示还有第二层运行覆盖。ApplicationRoute限流只能用于最终有效认证为ApiKey的路由，匿名路由必须选Route维度；保存绑定、预览和编译均校验这一组合。

## 6. 限流配置与执行语义

|字段|取值/校验|新建表单默认值|
|---|---|---|
|algorithm|固定 `TokenBucket`|TokenBucket|
|keyBy|`Route` 或 `ApplicationRoute`|ApplicationRoute|
|refillTokens|整数1–1000000，每个windowMs补充的令牌数|1000|
|windowMs|整数10–600000毫秒|1000|
|burst|整数1–1000000，桶最大容量，且不小于refillTokens|1500|
|redisFailureMode|`Reject` 或 `Allow`|Reject|

默认值只是可修改的新建表单值，不会自动绑定到已有路由。额外校验 `burst × windowMs / refillTokens ≤ 3600000ms`，限制满桶补充时间和TTL。每次通过消耗一个令牌，桶初始为burst；连续补充速率是refillTokens/windowMs。没有排队或主动延迟。

Redis单键原子脚本完成读状态、补充、消耗和TTL设置。时间来自Redis TIME，使用不倒退的有效时间；运算精度足以保证并发情况下不超发。Key包含运行环境、策略运行身份、路由ID；ApplicationRoute额外包含已认证ApplicationId，不使用原始API Key、IP、Header、查询字符串或用户提交标识。不同凭证属于同一应用时共享额度。网络超时后的结果不确定时不自动重试消耗命令，避免重复扣令牌。

空闲TTL为满桶补充时间的两倍、向上取整且至少1秒，上限7200秒；过期后新桶为满桶。共享同一策略的不同路由各自计数，两节点对同一路由/应用使用同一Key。所有节点共享同一Redis，不提供降级为节点本地额度的隐式路径。

额度不足：返回429，JSON `code=rate_limit_exceeded`、请求/Trace标识；Retry-After按下一令牌可用等待秒数向上取整且至少1。响应不包含Redis key、API Key或Secret。

Redis连接/脚本故障：Reject返回503、`rate_limit_store_unavailable`；Allow继续调用并记录 `RateLimitBypassed`。两种行为在表单、JSON、发布风险提示和观测中都可识别。Allow不承诺故障期间维持全局额度。Redis决策等待使用独立、可部署配置的100ms默认预算，达到预算即执行对应故障策略；客户端请求取消不当成后端失败。Redis重启丢失计数可能重新获得burst，这是瞬时运行状态边界，不将其描述为持久配额或计费系统。

## 7. 熔断配置与状态机

|字段|取值/校验|新建表单默认值|
|---|---|---|
|samplingWindowMs|1000–300000，1000的整数倍|30000|
|minimumRequests|整数1–1000000|20|
|failureRatio|有限数值，大于0且不超过1|0.5|
|openDurationMs|整数1000–300000|30000|
|halfOpenMaxRequests|并发探测上限，整数1–10|1|
|halfOpenSuccesses|所需累计成功，整数1–100|3|
|failureStatusCodes|不重复的500–599整数集合，最多100项，可空|500–599|
|countTimeouts|boolean|true|
|countConnectionFailures|boolean|true|

至少配置一种故障来源。状态键为节点实例、策略运行身份、路由ID、RuntimeClusterId；按路由保护当前后端集群，所有Destination共享该路由的熔断状态。本批不实现每Destination独立熔断。节点间不共享故障统计，不承诺同时打开或恢复。

- Closed：允许请求；使用单调时钟和1秒有限环形桶统计最近窗口内完成的上游尝试。有效样本达到minimumRequests，失败比例达到failureRatio时打开。
- Open：不请求后端，返回503、`circuit_open`和剩余等待的Retry-After；等待结束，下一次真实请求触发HalfOpen。
- HalfOpen：按上限允许探测，其余立即503。上游2xx/3xx是成功；累计达到halfOpenSuccesses后关闭并清空窗口。任一配置的失败重新打开、重置等待。未被归类为失败的4xx/5xx不作为恢复成功，释放探测名额，等待下一请求。

普通Closed窗口中，完成的上游响应计入样本，只有配置状态码计失败；代理连接故障、网关超时根据开关计失败。ClientAborted和主动策略拒绝不进入熔断样本。429/401/403不属于配置的失败状态码；网关生成的429/认证拒绝发生在熔断之前，也不进入样本。

请求读取状态后可能与其他请求并发完成；用状态epoch避免旧Closed或旧HalfOpen请求完成时将新的Open状态错误关闭。HalfOpen探测名额在异常/取消路径释放，只有已进入对应epoch的真实成功能贡献恢复次数。所有状态更新为并发安全、有限空间操作，不引入业务数据库请求。

节点重启、策略运行身份或后端集群内容变化时熔断从Closed开始。配置内容与运行身份相同的热发布不因为deploymentSequence变化而清空状态。已租用旧generation的请求保持旧策略引用；退役状态在没有请求使用后释放，避免无限保留。节点独立熔断是运行保护，并非健康检查结果，不能把Open写成Destination Unhealthy。

## 8. 网关顺序与请求归属

执行顺序固定：取得路由generation lease → ApiKey认证/授权 → 限流 → 熔断准入 → Destination选择及代理 → 熔断完成记录 → 请求观测。超时仍由对应路由/YARP请求超时机制实施。认证中间件必须将ApplicationId放入独立请求执行上下文，流量策略不能依赖可关闭的Telemetry状态获取身份。

限流、熔断、认证和代理均从同一租用generation读取运行配置，不能调用Current混用新旧版本。所有拒绝都在发送后端请求之前决定；已消耗令牌的请求若随后被熔断拒绝，不返还令牌，表示该路由的到达请求额度。即使关闭遥测，策略行为保持一致。网关数据面不查询PostgreSQL、不加载控制面Policy表。

## 9. 冻结发布与运行快照2.1

2.1在RuntimeRoute增加 `policyBindings`（运行策略ID、priority）；RuntimePolicy增加 `sourcePolicyId`、`sourceRevision`。运行策略ID取源ID、修订、类型及规范化配置的Canonical JSON的SHA-256前128位，以统一字节序构造UUID；编译器发现相同运行ID对应不同内容时拒绝编译。同一源策略的多个冻结修订可以同时存在。不能用源ID覆盖baseline中的旧配置。

每个启用绑定必须指向存在、同Scope、已严格校验的运行策略；同一路由同类型最多一个。认证、超时仍折叠为路由值，绑定供管理解释；高级策略在网关执行。禁用的工作策略不生成有效绑定，影响预览必须说明保护被移除或回到默认值。

部分发布按选中的API替换路由及其绑定，保留未选API的运行内容。根据最终路由引用集保留所需运行策略，删除未引用的2.1策略；不能因编辑一个共享策略而让未选路由自动获取新修订。2.0 baseline的路由保持原先折叠的认证/超时语义，没有高级绑定；历史原始快照不被重写。

预览返回全部候选资源及修订，包括Policy、Route绑定（通过Route Revision）和已有API/版本/后端/应用授权。创建发布必须提供预览资源修订全集；遗漏返回422，不匹配返回412。预览接口与客户端一起适配，不只增强服务端而让旧提交无解释失败。候选构建与工作配置写入使用既有治理锁，确保冻结读取一致。

生产仍是现有两级独立审批。提交后的候选内容不可被后续工作编辑改变；改变候选必须生成新的发布并重新审批。共享策略跨API、跨环境的受影响清单区分工作绑定、本次候选和当前运行修订；未选路由明确仍用旧修订。发布详情和脱敏快照展示策略差异，不包含凭证。

新策略修订得到新的限流Key和熔断状态，即以burst/Closed开始；编辑器与发布Review提示这一影响。回滚保留历史运行身份：未过期Redis桶可以继续使用，已过期则重新满桶；熔断历史状态若已释放则从Closed开始。回滚保证配置恢复，不保证回到历史瞬时计数。

## 10. 协议兼容与节点能力

新网关读取2.0和2.1；2.0只运行既有认证/超时，2.1校验完整绑定和四种已支持类型，未知协议/类型拒绝激活并保留LKG。输出若整个最终快照均无高级绑定可保持2.0；只要任一路由包含高级策略则输出2.1。2.0输出使用原字段格式，省略新增绑定/来源字段，不携带未执行的高级策略；2.0输入出现高级绑定或高级类型时明确拒绝，不能静默忽略。2.1输入必须验证认证/超时绑定与其折叠路由值一致。

注册和心跳增加可选 `supportedSnapshotSchemas`；旧客户端缺失时视为仅支持2.0。值只接受有限白名单、去重并限制长度；合并到既有GatewayNode.Metadata，不覆盖其他元数据，并关联当前InstanceId。重新注册必须刷新能力，不能继承旧实例能力。服务端不依据AppVersion字符串推断支持能力。

2.1发布前（含回滚/重试的目标快照）校验全部已启用目标节点在线且支持目标协议；Worker持锁构建时再次验证。缺失能力返回明确 `gateway_schema_unsupported`，不更新desired指针、不增加sequence、不缩减确认节点、不发送不兼容快照。发布前后实例替换仍使用既有实例ACK规则；不兼容新实例不能产生成功ACK，发布必须如实失败/待恢复，不能宣称原子升级整个集群。

升级顺序是控制面/Worker → 兼容新网关 → 确认全部目标能力与心跳 → 发布高级策略。已有2.0运行快照、LKG和业务数据可继续读取。回滚至历史2.0使用原字节、原hash、新deploymentSequence；带策略的历史2.1也可正常回滚、重试。不能直接将运行2.1的节点镜像降为只识别2.0的版本；先正常回滚配置、确认ACK，再处理软件降级。

## 11. 可观测性与信息边界

请求日志/Trace扩展受控属性：`policyId`（源ID）、`policyType`、`policyDecision`、`policyRevision`、`rejectionReason`。取值只由系统生成，投影层/白名单/DTO/CSV一起适配，旧记录字段缺失保持可读。保留既有Outcome语义，不让旧查询因新增不识别的Outcome丢弃整条记录。一次请求可带限流和熔断两条有限决策，Trace详情显示它们与最终HTTP状态的对应关系。

新增策略决策计数器，标签限于环境、节点、源PolicyId、类型、Decision；不带ApplicationId、TraceId、RawPath、运行修订或Redis key，避免无界维度。决策至少区分限流通过/超额/存储故障拒绝/降级放行，以及熔断通过/打开拒绝/半开探测/状态转移。

监控保留已有HTTP429及整体5xx口径，另显示熔断拒绝与限流存储故障；网关生成503不能显示为某Destination真实返回的5xx。日志过滤和Trace可定位策略拒绝；编辑器可按环境/API跳转已有观测页。告警规则本批可继续使用真实429/5xx现有指标，不为未支持的新指标伪造规则测试成功。

策略统计沿用现有Scope与SourceState：缺源、时间窗口覆盖不足、采样不足仍显示Unavailable/Partial和空值，不能补零。策略配置JSON不含Secret；日志、Trace、审计、截图和交付证据均不得保存Raw API Key、Cookie、Redis连接密码或令牌桶内部key。

## 12. 模块边界与运行约束

|模块|责任与依赖|
