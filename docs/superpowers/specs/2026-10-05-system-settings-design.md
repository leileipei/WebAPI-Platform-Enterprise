# 第 40 页：平台系统设置实施设计

状态：用户已于 2026-10-05 确认本设计，采用“平台级先行”范围；实施计划待审阅，尚未开始产品实现或部署。在现有核心、观测、流量策略及 4192 升级基础上编制。本稿不自动提交。

## 1. 目标与来源

将原第 40 页 `/settings/system` 接入真实 PostgreSQL、服务端权限、校验、修订冲突和审计，保留现代企业控制台 Shell、原五个设置分组、十七个字段及保存/配置测试流程。明确字段保存后的实际作用，保留原账号、审批流程、运行快照及业务路由。

原文来源：`WebAPI_Platform_Enterprise_V2_产品原型与数据架构设计.docx` 第 4.40 节和第 5.2.36 节；现有原型为 `prototype/src/pages/Governance.jsx` 的 Settings。原文指定平台级设置、`system.manage`、SecretRef、校验、影响提示和危险设置二次确认。数据字段为 key、scope_type、scope_id、value JSONB、updated_by、updated_at。本稿中的参数范围、并发协议和生效分类是建议设计，不作为原文已有指令或能力。

当前真实工程没有 system_settings 实体或读写接口，权限目录已定义 system.manage。会话 Cookie 固定 8 小时，新账号密码最低 16 字符，路由基础默认超时 30000ms，网关配置轮询等待 2 秒，控制面请求体上限显式配置为 8MiB。原型建议值不能覆盖这些现有事实。

## 2. 方案选择与本期边界

推荐方案：**平台级配置治理，加少量真实消费者，并逐字段展示生效条件**。五组十七字段均保留，支持受控持久化和结构校验；会话 TTL、密码策略、新路由默认超时及审计导出开关接入实际行为。生产两级独立审批保持现有约束。需要部署、通知提供方或清理流程的项目明确为未应用配置。

备选方案一是只接设置存储，所有字段都不作用于运行行为；交付快，但缺乏实际消费，故不推荐。备选方案二是一次完成多级继承、部署热更新、自动清理及 SMTP/Webhook 投递；涉及身份归属、快照历史、运行协议、秘密解析和外部发送，范围过大，留到独立阶段。

本期不实现组织/项目覆盖、OIDC/SSO、外部通知发送、秘密管理器连接、自动删除历史数据、网关设置热更新或 4192 自动升级。部署和源码提交仍各自遵循既有明确授权范围。

## 3. 字段与生效矩阵

页面同时区分“已保存配置”“实际消费者”“待部署/配置意向”。没有消费者的字段不得显示“已生效”。表中的范围是本期拟采用的服务端验证约束；建议值只用于未保存的表单展示，不冒充运行值。

| 分组 / 原字段 | 稳定键与验证 | 本期消费者 / 生效条件 | 初始依据 |
|---|---|---|---|
| 安全 / Session TTL 分钟 | sessionTtlMinutes，整数 5–1440 | 新登录票据设置明确到期时间；不延长或立即撤销既有会话 | 当前 480 |
| 安全 / 密码最小长度 | passwordMinLength，整数 16–128 | 后续创建本地账号，现有密码继续正常认证 | 当前 16 |
| 安全 / 密码复杂度 | passwordComplexity，LengthOnly / LettersAndDigits / UpperLowerDigitSpecial | 与最小长度一起校验后续创建账号；不记录密码 | 当前仅长度；保留原型的两类复杂度选项 |
| 安全 / Allowed Origins | allowedOrigins，最多 32 个精确 origin；不允许通配符、userinfo、query 或 fragment | 配置意向，未接跨域应用；同源 CSRF 写保护保持现状 | 当前同源保护；意向初始空列表 |
| 发布 / PROD 默认审批 | productionApprovalLevels，固定 2 | 展示当前生产双层独立审批约束；1 级选项显示不可用及原因 | 当前两级约束 |
| 发布 / Snapshot 保留数 | snapshotRetentionCount，整数 10–10000 | 保留目标配置，未执行历史清理，不删快照或发布记录 | 原型建议 50，非已应用值 |
| Gateway / 默认超时 ms | defaultRouteTimeoutMs，整数 1–300000，与当前路由及超时策略上限一致 | 新路由未显式指定基础超时时使用；编辑旧路由不读新默认；工作配置仍正常审批发布 | 当前 30000 |
| Gateway / 最大请求体 MB | maxRequestBodyMb，整数 1–256 | 待部署配置；不声称已改网关或控制面限制 | 原型建议 20；网关实际值未由本模块报告 |
| Gateway / Config 刷新间隔秒 | configRefreshIntervalSeconds，整数 1–60 | 待部署配置；不影响现有两秒轮询及通知刷新 | 当前两秒；建议沿用 2 |
| 审计 / 日志保留天数 | auditRetentionDays，整数 30–3650 | 保留目标配置，未执行删除，审计记录保留 | 原型建议 365，非已应用值 |
| 审计 / 允许导出 | auditExportEnabled，布尔 | 新增真实审计 CSV 导出；audit.read 与授权范围另行复核 | 新功能默认允许，仍需独立审计读权限 |
| 通知 / SMTP Host | smtpHost，可空，最长 253 字符；只允许主机名或 IP，不接收 URL / 认证信息 | 配置意向、结构校验；不连接、不发送 | 原型样例不写入真实配置 |
| 通知 / SMTP Port | smtpPort，可空或整数 1–65535 | 同上；Host/Port/From/SecretRef 的完整性联合校验 | 建议 587，未配置 |
| 通知 / From Email | fromEmail，可空，邮箱格式及长度 ≤254 | 同上 | 未配置 |
| 通知 / SMTP SecretRef | smtpSecretRef，可空，只接受规定的 vault 引用语法 | 仅引用持久化；不解析秘密 | 未配置 |
| 通知 / Webhook URL | webhookUrl，可空或 HTTPS；拒绝 userinfo、query、fragment；最长 2048 | 配置意向；不访问 URL、不跟随跳转 | 未配置 |
| 通知 / Webhook SecretRef | webhookSecretRef，与 SMTP 引用规则一致 | 仅引用持久化；不解析秘密 | 未配置 |

路由服务与超时策略验证器均已核对为 1–300000ms，本模块采用同一范围，不扩大旧验证器上限。本期不新增“密码重置/首次改密”，密码策略消费者只覆盖现有本地账号创建命令。

SMTP 四字段全空表示未配置；开始配置 SMTP 时必须完整提供四字段。Webhook URL 有值时必须提供 SecretRef；没有 URL 不能单独保存 Webhook SecretRef。SecretRef 仅使用 `vault://<provider>/<path>`，拒绝空 provider/path、控制字符、userinfo、query、fragment；校验引用格式不证明引用存在。

## 4. 数据与修订

新增 SystemSetting 实体和迁移，保留原 key 主键与 scope_type / scope_id / value / updated_by / updated_at；增加 revision bigint（从 1 开始，乐观并发字段）。五个允许的 key 为 `system.security`、`system.release`、`system.gateway`、`system.audit`、`system.notification`；每行 JSONB 为一个已定义分组，解析为强类型值，拒绝未知属性、重复 JSON 属性、类型错误和超限请求。

本期写入限定 scope_type=system、scope_id=null；不能通过客户端参数创建 org/project 记录。保留范围列，不实现继承。不宣称现有 key 单列主键已能支持同名键的多范围继承；将来扩展需单独设计唯一性和迁移。

迁移只创建空表和约束，不把原型样例植入部署。未保存分组的管理视图修订为 0，展示明确的当前默认/建议来源；首次写入要求 If-Match 修订 0。首次并发写入在既有授权事务锁内串行验证；后续修订递增。不同分组不互相覆盖。同一分组在一个事务内整体保存，拒绝未知 key、范围和字段。

未保存行时实际消费者继续使用兼容默认：480 分钟、16 字符、LengthOnly、30000ms。不得因读取或预览创建设置记录。部署依赖或 DB 查询失败不悄悄使用更宽松配置；返回正常故障状态供排查。保存成功才可显示已保存配置。

## 5. 权限、命令和确认

设置管理读取、校验、预览和保存都沿用 system.manage，并使用 Guid.Empty 平台资源引用，复用当前服务器对系统 PlatformAdmin 身份的检查。组织管理员、项目管理员、审批人或有自定义同名角色的用户不能靠 Scope 或同名角色取得平台权限。

所有写接口执行既有 Origin/CSRF 检查；保存使用 If-Match、Idempotency-Key 和既有 pg_advisory_xact_lock(8901202)，在事务内重新授权。缺少修订或过期修订返回既有修订协议的错误，旧内容不被覆盖；幂等重试不得重复增加修订或写审计。

保存前服务端生成影响预览；确认凭证通过持久 DataProtection 保护，绑定用户、分组、旧修订、规范化值摘要和五分钟到期时间。值或权限变化需重新预览。凭证不授予权限，事务内仍重新鉴权。确认凭证不包含密码、SecretRef 原文或完整通知 URL。

幂等请求摘要覆盖语义配置、旧修订和变更操作，排除可重发的预览凭证。已提交的相同幂等请求先返回原结果；未提交的新命令才检查凭证时效和当前 ETag，避免合法重试因旧 ETag 失败。不同语义复用键返回 409。此顺序作为独立集成测试项。

更新审计记载分组 key、字段名、修订、配置摘要、操作者和请求 TraceId。非敏感项可提供安全差异，引用只记录存在性/引用类型和变更标志；不通过扩大通用审计白名单泄漏任意 value JSONB。

## 6. 接口建议

| 接口 | 行为 |
|---|---|
| GET /api/v1/settings/system | 五个分组摘要；权限检查；Cache-Control: no-store |
| GET /api/v1/settings/system/{group} | 强类型字段、来源、生效分类、保存修订及 ETag |
| POST /api/v1/settings/system/{group}/validate | 结构与跨字段校验；只读、不联网、不保存；要求 CSRF |
| POST /api/v1/settings/system/{group}/preview | 校验、当前修订差异、消费者影响和确认凭证；不保存、不写业务审计 |
| PUT /api/v1/settings/system/{group} | 确认、鉴权、修订及幂等保护后事务保存 |
| GET /api/v1/environments/{id}/route-defaults | 仅返回基础超时默认；要求该范围 route.write，不能读取平台安全/通知配置 |
| GET /api/v1/audit-logs/export | 当前授权审计范围内 CSV；受导出开关及 audit.read 共同约束 |

group 为 security / release / gateway / audit / notification。无任意键增删接口，也不提供“恢复全部默认”或清理数据快捷动作。来源与生效模式可为 CodeDefault、Saved、PrototypeSuggestion 和 NewLogin / NewUser / NewRoute / ExportRequest / DeploymentRequired / ConfigurationIntent / FixedConstraint。

SecretRef 原文保存后不回显。读取返回 hasConfiguredReference / provider 等安全元数据；写入使用明确的 Keep / Replace / Clear 操作，Replace 才携带当前输入的 reference，其余操作不得携带引用原文。编辑支持“保持现有引用”“替换”“清除”；不以占位符字符串覆盖已存引用。替换值只来自当前输入。校验和预览的响应、Problem Details、CSV 与审计不得回显秘密输入。

“测试配置”返回 `testKind=StructuralOnly`，消息明确“结构校验通过；未解析 SecretRef，未连接 SMTP/Webhook，未发送通知”。源字段保留，但不沿用原型的模拟连接成功提示。

## 7. 实际消费者

1. 登录事务先取得既有授权锁，再锁定用户并读取当次 TTL，避免与用户停用命令形成反向锁序；为新 Cookie 明确设置 IssuedUtc / ExpiresUtc。仍为非持久 Cookie、无滑动延期，安全 stamp 撤权逻辑保留。保存 TTL 不修改既有票据。
2. 本地账号创建在既有授权事务内读取密码策略，在哈希前校验。既有账号认证、bootstrap 凭据和节点秘密不受新策略追溯影响。
3. 新路由省略 timeoutMs 时，在路由创建事务内读默认；显式值优先。旧路由编辑必须提交已有或新显式值，不能因省略而被默认覆盖。新建表单显示来源并预填；已有详情保留基础超时/策略有效超时的现有区分。OpenAPI 仅在新增路由路径读取默认，覆盖旧路由不引入此默认的附带改变。
4. 审计导出复用现有服务端授权范围的查询，不把权限提升为全平台。限制最多 10000 行 / 8MiB，固定上限 ID 与过滤条件，输出已知行数和截断标志，处理 CSV 公式前缀。分批及发出前重验权限与开关，在既有授权锁内完成最终准入；此前已撤权/关闭则丢弃 buffer。最终准入后不承诺撤回已发送数据。导出数据中不包含原始 IP、秘密或未经审核的任意 JSON。

## 8. 页面与关键交互

在现有 Shell 增加 `/settings/system` 导航，沿用原五组侧边切换、标题、保存按钮、字段网格、校验提示、影响提示和确认对话框。平台设置不受顶部当前组织/项目选项误导；页头明确“平台级”。第 40 页能力映射在实际实现及验收后更新，SSO 页面保持后续状态。

每个字段展示当前来源和生效条件；待部署字段显示“已保存，未应用到运行实例”，通知显示“配置意向”。生产审批展示双层固定约束，单级选项保留但禁用。页面不得展示未知网关请求体限制为 20MB 已生效。

切换分组、导航、浏览器后退与关闭页面保护未保存输入。412 保留全部输入，提供明确“读取最新并重新核对”，不自动覆盖或重试写入。撤权或会话失效立即清空服务器数据与 SecretRef 替换草稿，不凭前端按钮代替服务端授权。保存期间避免重复提交，幂等键只在语义输入变化时更新。

审计页新增 CSV 导出入口；列表授权返回安全的 exportAllowed 能力信息，不返回完整设置。只有当前 audit.read 能力时展示，关闭开关后禁用并说明。服务端对同页及直接 URL 均执行相同开关和范围保护。

## 9. 实现隔离与验收

书面设计获审阅后再准备实施计划。产品实现从已固定的 79990836 提交建立独立系统设置工作树，保留 traffic-policies 的封存证据、复验文档和原仓库未提交文件；不在现有长期数据上开发或故障注入，不自动提交、推送、合并或切换 4192。

验收包括：

- 原十七字段映射、验证范围、五组默认来源和 SecretRef keep/replace/clear。
- 真实 PG 迁移及保存/重启后读取；首次修订 0 竞争、同组 412、不同组不覆盖、整组回滚。
- 非平台身份 / 同名角色 / 撤权、CSRF、预览凭证绑定与到期、相同幂等键重放不重复审计、不同输入 409。

- 新路由默认及显式优先；编辑旧路由、已有 Snapshot 字节和当前请求不受设置保存影响；高级策略仍审批生效。

- 待部署与通知意向不触发进程重启、HTTP/SMTP 连接、删除历史或假测试成功。
- 1440px 真实浏览器：17 字段、确认预览、412 保留输入、SecretRef 不回显、未保存保护、撤权清数据、CSV 导出及页面状态。
- 运行已有相关核心/流量策略回归；真实双网关隔离夹具核对默认变更需要正常发布，不自动改原业务。

源码、实际镜像、测试日志、浏览器截图和结果分层记录；新 ZIP 使用独立名称及逐文件摘要，排除凭据、数据、运行目录和缓存。本期不把部署意向字段计为已完成热更新/通知/清理能力，不把隔离验收计为已升级 4192。
