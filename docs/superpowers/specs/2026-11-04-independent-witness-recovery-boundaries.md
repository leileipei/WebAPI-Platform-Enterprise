# 独立见证与恢复边界：实施前约束

日期：2026-11-04。用户已选择独立时间源与安全历史见证的可插拔方向，未配置时保护性阻断。本文整理下一步协议必须满足的约束；并不表示已接入真实服务、完成协议或允许治理 2.4 签发。

## 信任与当前能力

时间来源须提供有界时间，安全历史见证须独立持有可核验、不可回退的环境高水位及写入顺序。两种能力可以由同一外部系统提供，但该系统的持久状态、备份和信任根不能与平台数据库和网关一起被无差别回滚；独立性、时钟精度、密钥管理及持续运行能力都需要实际运维验收。不同的配置项或有效签名本身不能证明独立性。

当前诊断组件使用每次随机挑战，绑定用途、环境、节点及实例、代次、账本序号和账本头；对时间和历史证明分别固定来源与签名公钥，检查签名及有限时间窗口。见证的 `Confirmed` 与 `Sequence` 目前只表明签名者对该挑战给出了确认，不证明它记住了更高的旧状态。诊断结果不能作为授权能力使用。当前时间检测基于进程内单调时间，不能证明休眠、虚拟机快照恢复或进程重启后的绝对时间。

响应读取采用有界流；单次诊断只读取每个响应至多 32 KiB 加一个探测字节。适配器和传输层必须独立实现响应大小、连接和时间上限，不能在返回流之前无界缓存。当前签名端与验证端使用同一序列化实现，尚未有由另一实现生成并校验的固定协议向量，因而不宣称跨服务互通。

## 写入与恢复约束

下列顺序是待实现的安全约束，不等同于一个已经验证的分布式事务实现：

1. 在环境级互斥和实际旧写入者隔离已成立时，独立比对数据库与见证的环境身份、代次、序号、账本头及未完成意图；任一来源不可用、回退或不一致即停止签发。
2. 在独立见证中以幂等操作身份和条件更新持久记录准备意图，绑定旧头、新事件、顺序及必要的恢复材料。准备后不能再基于旧头签发新的受保护租约。正在签发与写入的并发必须由见证及实际控制面栅栏共同约束，而非只靠单个进程锁。
3. 在数据库事务中提交与准备意图完全一致的事件及待完成标记；随后在见证中确认，再将数据库标记完成。确认丢失或任何阶段异常都不能推断为成功，须重新读取独立见证并执行可验证的前向恢复。
4. 已签发的网关租约可能仍然有效。正式撤旧和硬截止必须将既有租约、时钟误差、传输和处理预算纳入截止前边界；不能只因见证进入准备状态就假定已发租约失效。网关本身还须验证当前实例、独立时间和恢复来源。

| 状态或故障 | 安全处理要求 |
| --- | --- |
| 见证已准备，数据库提交结果未知 | 不签发；依见证中的独立持久意图核对并前向恢复，不能仅凭数据库未见事件就撤销意图 |
| 数据库已提交，见证确认结果未知 | 不签发；按同一操作身份查询见证并幂等确认，不能凭本地成功日志推断外部已提交 |
| 见证已确认，数据库恢复到较旧状态 | 不签发；必须以可信材料补齐或恢复，不能以较旧数据库重建见证高水位 |
| 见证恢复到较旧状态 | 不签发；要求独立的防回退证明或保持未知，不能用数据库单方面证明见证本身可信 |
| 数据库和见证共同回滚或来源独立性无法证明 | 保持未知并阻断；该模型没有可证明的共同回滚检测能力 |
| 旧控制面仍可写数据库或持有效签名能力 | 不开放治理准入；先完成实际进程、数据库角色和密钥的写入栅栏验收 |

实现时还需明确初始化和证据续期、挑战单次使用、并发顺序、密钥轮换、历史材料大小、失败审计、恢复权限与运维操作；不能把数据库中的 Hash 链或本地测试文件当成独立见证。

## 验证门禁

需先用明确的故障注入和状态机测试覆盖每个崩溃边界、重放、并发签发／写入及所有单侧恢复；再用实际独立服务、实际数据库角色和双网关验证。最终还须检查旧网络策略 2.3、发布回滚、普通／正式轮换、硬截止和监控语义。未通过之前，公开租约签发保持 503，治理快照运行准入保持关闭。
