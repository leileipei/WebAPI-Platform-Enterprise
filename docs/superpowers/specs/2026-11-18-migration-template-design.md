# 测试数据库迁移复用设计

用户授权：在独立分支优化重复迁移，前后对照，保留旧资料，门槛不变；本机全量与GitHub必需检查通过才合并。依据前轮[测量](../../deployment/integration-test-timing-20261118.md)。

采用每个测试类独立拥有的、真实迁移后封闭连接的临时数据库模板。普通业务用例显式选择模板，并各自克隆独立数据库；仍创建各自用户、真实登录、运行原断言及销毁数据库。默认ApiFixture和PostgresDatabase路径不变。

## 方案取舍

- 逐用例真实迁移：最简单，保留为默认及迁移、安全、权限、故障、超时测试路径。
- 每类临时模板：本轮选择；仅减少选定普通业务测试重复迁移，类结束明确清理，便于证明生命周期和隔离。
- 跨进程/跨运行持久模板：本轮不采用；需要额外的失效、所有权与恢复协议，收益尚未测定。

模板以唯一名称创建，从当前已编译的模型、迁移和提供者生成；记录相关程序集MVID与迁移列表的指纹。无持久缓存查找，不跨测试类、进程或运行复用，因此源代码重新编译、模型变更和数据库设置变更都会创建新模板。模板不含业务种子、用户或秘密。迁移完成并关闭所有模板连接后，设置ALLOW_CONNECTIONS=false；每次克隆只在同一模板实例的互斥区间内执行，销毁也用同一锁，禁止关闭后继续克隆。

连接必须先关闭，禁止新连接本身不会终止已有会话；克隆开始时模板必须没有其他连接。依据[PostgreSQL模板数据库说明](https://www.postgresql.org/docs/current/manage-ag-templatedbs.html)，并由本轮真实数据库测试验证所使用镜像的行为。

迁移失败须传播错误并清理已创建模板，不能退回空库或旧模板取得通过。克隆失败不发布部分初始化的夹具。保留既有retain诊断语义：显式保留模式下留存数据库用于诊断，但逻辑实例仍关闭，失败后不能继续克隆；普通模式显式销毁模板与各克隆，并由既有所有权脚本清理自有容器/卷。全局清池、数据库持久性、CI超时、并发、依赖及产品代码均不调整。

首批仅从CatalogTests、ImportSessionTests、SchemaValidationApiTests、VersionContractSourceTests逐方法选入普通内容行为；授权撤销、隔离可见性、安全输入、回滚/故障、期限和迁移用例保持原始路径。每次选择必须记录方法清单，不能通过类名隐式推定全部可复用。

迁移自身生成的系统元数据会随模板复制，例如数据库时钟水位的初始时间；模板不提供“每例在当前时刻重新执行迁移”的语义。因此时钟、安全准入、迁移回执、恢复、初始化及新鲜度边界禁止选入；不把内容测试的模板资格推广为这些边界的验证。

## 验证

新增真实PostgreSQL测试：迁移结构及历史等价、原默认空库、并发独立克隆、业务数据不污染模板/后续克隆、模板不可连接、克隆销毁后模板仍可用、模板销毁后不可再克隆、迁移失败清理且不回退。不同模板实例指纹相同但数据库身份不同，证明不持久共享。

性能用相同81项现有测试集合、固定脚本/镜像/主机先后独立执行，不同时运行其他测试；保留每轮原日志及脚本/框架时间，不以累计测试秒数冒充墙钟收益。样本收益不外推为全量收益。最终本机Domain、Integration、Gateway、Node、Python及前端构建全部通过；GitHub四项必需检查及分支保护不变，合并前重新核对确切提交。
