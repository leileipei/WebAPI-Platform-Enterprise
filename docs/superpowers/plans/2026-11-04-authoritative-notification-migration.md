# Authoritative Notification Migration Implementation Plan

> **Execution:** 本会话直接执行；用户要求保留全部历史失败与数据，验证通过前不得提交、合并、推送或部署。

**Goal:** 让官方历史库迁移入口使用现有 .NET 通知校验器作为权威，并在完整迁移窗口保护被验证的数据。

**Architecture:** 用户已选择 A：需验证旧通知数据的历史库使用受控 .NET 迁移器；独立 SQL 在首项写入前对这类数据保护性阻断。两条入口的迁移期间应持有事务内写入保护；实际旧进程、认证和迁移后隔离仍需独立环境证据。

**Tech Stack:** .NET 10、EF Core、PostgreSQL 17、xUnit。

**Spec:** `outputs/merge-check-20261104-apzqzhfd/通知迁移校验与隔离方向比较-20261104.md`，用户已选择方向 A。

## 全局约束与审查重点

- 不改已应用的历史迁移文件或历史结构指纹；保留 2.3 语义及其他既有业务。
- 无实际旧环境切换授权；所有运行测试只使用独立 owner 和一次性数据。
- 保留既有有效历史通知与告警内容、记录身份、修订及迁移历史；错误消息不输出配置或秘密。
- 独立 SQL 必须区分空库、无需历史通知校验的历史库和需要 .NET 校验的历史库；不接受伪造的会话变量作为验证证据。
- 事务内锁不证明事务外、同身份高权限、网络入口或迁移后隔离；这些缺证必须保留为门禁。
- 历史 `ExternalNotifications` 的原 SQL 检查会拒绝部分合法 .NET 输入；受控入口在同一锁定事务内完成 .NET 校验后，只替换固定哈希历史操作的校验块，原更新语句不变。历史源码与 ID 不变不等于 SQL 完全按原语义执行；构建身份及实际入口应进入交付证据。
