## 范围与设计

补齐真实治理 HTTP 命令与已有凭证创建回执重试的并发边界，覆盖权限删除、用户角色移除、用户范围撤销，各验证撤销先于重试、重试先于撤销两种顺序。采用现有 PostgreSQL 治理锁和锁等待观测方案，确认两个请求真实重叠后放行，不用固定睡眠猜测顺序。分别覆盖同进程和独立控制面进程。

独立管理员执行真实撤销接口；凭证操作者不是平台管理员。撤销先取得锁时重试返回 403；重试先取得锁时只能返回原凭证元数据，秘密和 API key 均为空。撤销完成后的原键重试和新键创建都必须拒绝。凭证、回执字节、应用修订和创建审计保持原值，撤销审计归属管理员。

相较随机并发压力测试，数据库队列观测能稳定覆盖两个交错。相较直接数据库删除权限，真实 HTTP 命令覆盖鉴权、修订校验、事务和审计。测试辅助逻辑仅放在测试文件，默认不改产品代码与 CI。
