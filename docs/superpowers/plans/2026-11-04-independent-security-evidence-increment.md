# 独立时间与安全历史见证：隔离实施增补

用户选择：没有或不确定是否已有独立见证；采用可插拔设计，未配置时保护性阻断。本文是已批准的治理 2.4 集成计划的增补，不代表真实可信源已存在或验收完成。

## 当前增量

1. 建立显式未就绪的治理租约签发边界；在见证协议、写入恢复和网关准入全链路接通前，无论签名密钥是否可用，都不得签发。将既有不具备独立见证的生成算法移到测试项目，生产程序集不包含该算法，保留其隔离行为测试；不把这些测试称为正式签发测试。
2. 分别定义可插拔时间源及历史见证输入，使用独立配置的受信密钥验证有界、严格编码的签名响应。每次挑战使用随机数并绑定用途、环境、节点、实例、账本代次、序号和头；拒绝缺失、伪造、重放、错误范围和未确认历史。假来源及测试私钥只存在测试代码中。
3. 采用进程内单调时间限制本次证明采集和验证的窗口；不能把该窗口声称为绝对时间、防休眠或重启证明。当前验证结果仅用于验证协议组件，不授予签发和网关准入能力。
4. 通过先失败后通过的限定测试，保留原始日志；再回归旧签发算法、安全边界及受影响的主线功能。历史失败和 G14 不变，不运行正式性能测试。

## 后续合并门禁，当前增量不会豁免

- 设计并实现带独立见证持久顺序、预备／提交／确认和前向恢复的完整协议；单个来自见证的签名不能证明写入事务在崩溃或恢复后完整。
- 明确受信源独立性、首次安装、密钥轮换、进程和节点重启、时钟误差与可持续性；签发必须在事务内外各安全点重新核对，并覆盖提交后的不确定性。
- 每个网关独立验证可信时间和恢复来源，防止本地高水位整体回滚；旧控制面／Worker 实际写入隔离、双节点确认、硬截止撤旧和旧 2.3 行为还须单独验证。
- 实际外部可信服务的部署、持久性及故障演练目前没有证据；单元测试中自签名模拟不能代替真实服务验收。
- 保留当前运行环境和所有历史证据；不推送、不部署 4192；仅在原计划全部门禁通过后才提交、合并。
