# 首期治理授权与事务

服务端同时检查数据库中的用户状态、角色功能权限和数据范围。Scope沿用源文档read/read_write；组织范围只扩展同组织，项目范围只扩展同项目，环境范围只扩展该环境。匹配范围取并集，随后与角色权限取交集；没有Scope不能操作业务资源。治理的停用/启用允许查看与恢复原范围，业务访问仍检查上级状态。

单资源无读取权限返回404；写权限不足403，旧ETag412，进行中的发布阻止项目/环境停用409。关键命令统一事务和授权锁，授权变化与业务提交不能交错；审计失败时业务和审计一起回滚。审计仅捕获安全字段白名单，不保存密码、密钥或Cookie。

首组织创建需显式平台管理员授权，并为创建人建立此组织Scope。跨组织用户注册表、全局停用、整体角色及Scope分配仅平台管理员操作；组织资源与组织自定义角色按其Scope管理，不能给出自己不持有的权限。最后一位有效平台管理员不能停用或撤权。系统角色不可修改或删除，可通过自定义角色配置权限。

显式--seed-catalog初始化源文档9种角色及权限字典，--bootstrap同时执行字典初始化；不产生演示用户。可观测性、SSO等延期模块仅保留权限编码，未提供其实现。

当前采用统一控制面写锁，优先保证权限提交一致性；后续可通过授权版本和按资源锁优化并发吞吐。本机数据库/HTTP测试不是生产安全或性能验收。
