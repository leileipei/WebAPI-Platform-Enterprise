# 持久发布与重试约定

发布命令只把已审批的记录从 Ready 变为 Building，不改变环境目标指针。命令和构建 Worker 都重新检查实际发布人的有效账号、发布权限及数据范围。申请人与发布人分开记录，Worker 不会借用申请人的权限。

Worker 在数据库事务中锁定环境，并再次检查基线、版本内容 revision 与节点集合。至少两个节点已注册，全部启用节点必须具有有效实例身份和近期心跳；缺少或离线节点会明确阻止构建，不缩减确认目标。冻结候选所指版本若已被继续编辑，将拒绝发布并要求重新审批，保留新草稿。

同一事务保存精确快照字节、SHA-256、版本、冻结 nodeId / instanceId、环境目标指针、单调递增 deploymentSequence、Outbox 及审计。持久化即封存已下发版本，部分节点应用或最终失败都不能修改该版本内容。Publishing 表示等待真实节点确认，不代表已经成功。

授权检查与数据库提交共用权限变更锁。Building 队列期间撤权会阻止指针移动。数据库提交后的 Outbox 重试是完成已授权提交的持久事实，不会因之后撤权偷偷撤销或回退已提交目标；变更目标必须使用新的、经授权的发布或回滚流程。

Redis 是可重建缓存。每个环境完整写入 Envelope 和原始字节后才发送通知，Lua 使用十进制字符串比较 int64 sequence，避免超过 2^53 的精度丢失。旧事件不能覆盖新 sequence；相同 sequence 的不同字节或 Envelope 被拒绝。通知丢失不改变数据库事实，Worker 启动及周期补偿重建当前缓存。

Outbox 采用 30 秒租约和递增尝试次数。Redis 不可达时释放租约供重试；写入后崩溃由租约过期恢复，相同版本及 hash 保持不变。只有当前尝试可以标记完成，过期实例不能完成新尝试的租约。不会因重试新建 ConfigVersion 或 ReleaseTarget。

集成验证使用隔离 PostgreSQL 数据库与真实 Redis。节点集合在这一阶段由测试数据建立，不代替节点身份接口、真实网关加载和 ACK 验收；这些在后续节点与网关阶段完成。
