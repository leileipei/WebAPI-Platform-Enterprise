# 纯I/O裁决与有界排空模型

`io_coordinator.py` 只接收调用方给出的整数时刻和合成事件，返回状态与惰性意图。模块不读取时钟、文件或描述符，不创建管道/线程/进程，不发送消息、不执行关闭/终止，也不包含回调。未调用`step`时状态不会自行随真实时间变化。

这是截止、字节账与排空协议的模型，不是真实硬墙钟执行器。`grants_admission`、`io_stopped_proven`与`summary_durable`始终为false。观察完整也只返回`RETURNED_OBSERVED`，不代表业务或平台验收通过。候选预算没有因此冻结。

## 接口

- `IoLimits(...)`：冻结的数据值对象，明确全部绝对纳秒截止、排空窗口、日志/TRX/总证据额度、单块/队列/丢弃/事件/控制头上界。所有整数均排除bool，范围0至2^63-1；配置额度必须正数，截止顺序受校验。没有隐式生产预算。
- `IoDeadlineCoordinator(limits, attempt_epoch, start_ns, worker_epoch=..., leases=...)`：开始一个纯模型实例；初始`CAPTURING`不是启动环境或放行准入。epoch及lease仅为1至64字符ASCII关联值，不证明资源归属。
- `step(now_ns, event)`返回`{'summary': ..., 'intents': [...]}`。调用方必须单一所有者顺序调用；没有并发锁或线程安全承诺。`snapshot()`返回独立副本。已返回结果不可被晚到事件升级或改写。

事件为已解码的普通dict；字段数最多16，精确类型先检查，再比较身份。控制头是有界平面标量，不接受未知字段或任意嵌套对象；编码尺寸不超过配置值，最大4KiB。`pipe_data.data`单独为有界bytes，最大64KiB，不属于控制头额度。模块不提供真实IPC帧解码器。

事件类型：`clock_tick`、`pipe_data`、`pipe_would_block`、`pipe_eof`、`pipe_error`、`write_ack`、`finish_ack`、`worker_state`、`local_close_ack`，以及补全业务失败/TRX请求输入的`stop`、`copy_request`。具体必需字段和字面轨迹见`tests/local_diagnostics/test_io_coordinator.py`。

## 关键行为

- 当前接收时刻到达全局、收尾或I/O截止时，先裁决再处理事件；首次建立的排空截止若已到期，同一步也不能派发写入。进度、回执或排空不能延长绝对时限。
- 日志与TRX按预算域分别核算，且共享总证据额度。派发/排队前占用最大可能写入字节；有效部分ACK只结算实际增量，未终结部分仍占额度。超时、坏回执或未知结果不释放未决额度，不重投、不重启工作单元。
- 一个全局在途作业、一个有界排队槽。队列槽占满即保守锁存停止；已占用的证据字节可在期限内收尾。收到无对应在途任务的busy、unknown或finished工作状态后不再派发写入/finish；没有“恢复工作单元”入口。
- 只保留最近16条终结写入回执用于幂等去重。相同回执不重复记账，冲突回执失败关闭；更旧的回执保守拒绝，代价是可能额外拒绝合法但过晚的重放，而不无限扩张历史内存。
- 读端EOF、would-block、本地关闭和工作单元状态分开记录。本模块没有外部归属证明，所以不产生描述符关闭权限；未经请求的local_close_ack只记录未知状态并锁存失败。
- 每次poll意图交替排列仍未收到EOF的stdout/stderr，限定单次读取及绝对poll截止；两个通道均EOF后只等待在途写入确认，不再请求读取。工作截止尚未触发时，poll须最迟在工作截止返回；进入排空后使用排空截止。队列没有空间时不再请求读取新落盘数据；只能按剩余排空额度请求丢弃观测。公平性是模型意图，不是实际调度保证。
- 排空同时受时间、事件数和丢弃额度限制。超出读取/丢弃协议的输入块以`rejected_event_bytes`单列，失败并返回不完整，不通过截断数值把它伪装成合规丢弃观测。坏ACK越界前不提交字节计数。
- 只有两个真实合成EOF、所有作业终结、无遗漏/失败、且截止前收到有效持久性回执，才可得到完整观察。finish确认日志持久字节，不把未确认的TRX复制字节自动升级为持久化。原始输入内容不会进入安全汇总，但submit_write的惰性数据意图含已接纳的payload；调用方不能把整份Decision当作脱敏日志保存。

## 验证范围

目标检查只用假时钟、小整数绝对时间和字面事件，覆盖26个方案场景及独立回归。它们不使用sleep、管道、线程、进程或阻塞I/O。小整数仅用于验证相等/顺序边界，不证明真实纳秒内能处理消息。

```sh
python3 -B -m unittest discover -s tests/local_diagnostics -p 'test_io_coordinator.py' -v
```

历史上一次受限验证通过专用守卫运行，禁止实际网络、子进程、信号、线程、pipe及FIFO创建。当时旧套件中一项同时包含FIFO创建的检查按该轮限制标为NOT_RUN，源码不变；该记录只适用于那次受限验证。当前仓库的标准检查执行完整诊断包，不跳过该项；各轮结果以对应提交的日志为准，历史NOT_RUN不回写。

I/O停止、工作单元/适配器实现、OS调度与IPC、实际硬截止、资源归属/清理、SDK401、真实登录503、总配额及安全缓冲足够性仍需独立证据。原产品1000ms和全部运行准入条件不由本模型修改。
